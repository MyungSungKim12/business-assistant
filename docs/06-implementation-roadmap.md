# 구현 로드맵

각 단계는 이전 단계의 품질 검사(Ruff, mypy, pytest)를 통과한 뒤 진행합니다. 완료 기준은 기능이 보이는 것뿐 아니라 권한, 오류 처리, 테스트와 문서가 함께 준비된 상태입니다.

## 1단계 — 프로젝트 기반

**산출물**: uv/Python 3.13 워크스페이스, 공통 패키지, FastAPI 상태 확인 API, PySide6 최소 창, PowerShell 개발 스크립트, 입문 문서.

**완료 기준**: `scripts/bootstrap.ps1`으로 새 환경을 구성하고 `scripts/check.ps1`이 통과합니다. 서버의 `/api/v1/health`가 응답하고, 데스크톱 메뉴 셸이 Qt offscreen 테스트에서 생성됩니다.

## 2단계 — 사용자와 조직

**산출물**: Supabase Auth 어댑터, 회원가입·로그인·세션 갱신 흐름, 프로필, 조직, 멤버십과 역할 관리.

**완료 기준**: 인증되지 않은 요청은 거부되고, 사용자는 자기 조직과 역할에 맞는 데이터만 볼 수 있습니다. 로그인 만료와 네트워크 오류를 데스크톱에서 구분해 안내합니다.

## 3단계 — 구독과 권한

**산출물**: 상품·기능·구독 데이터 모델, entitlement 계산 API, 메뉴 권한 연결, 기기 등록 제한.

**완료 기준**: 상품 변경·만료·취소에 따라 entitlement가 정확히 바뀌며, 메뉴를 조작해도 서버 API 권한 검사를 우회할 수 없습니다. 기기 한도와 감사 로그가 테스트됩니다.

## 4단계 — 범용 업무 기능

**산출물**: 고객·거래처, 일정·할 일, 문서 자동화, 매출·지출, 파일·자료, 가져오기·내보내기, 보고서·분석의 공통 기반.

**완료 기준**: 모든 업무 데이터가 `organization_id`로 분리되고 RLS 테스트를 통과합니다. 각 기능은 필요한 feature code와 역할을 서버에서 검사합니다.

## 5단계 — 상용화

**산출물**: 서명된 결제 웹훅, 설치 파일, 자동 업데이트, 운영 배포 절차, 백업·모니터링·장애 대응 문서.

**완료 기준**: 중복 결제 이벤트가 한 번만 처리되고, 비밀값이 로그나 설치 파일에 포함되지 않습니다. 새 PC에서도 설치·업데이트·복구 절차를 재현할 수 있습니다.
