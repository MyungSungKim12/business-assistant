# Supabase와 SQL 적용

Business Assistant는 Supabase Auth, PostgreSQL과 비공개 Storage를 사용합니다. SQL은 자동으로 운영 DB에 적용되지 않으며, 대상 프로젝트를 확인한 뒤 번호 순서대로 실행합니다.

## 처음 만드는 프로젝트

Supabase Dashboard의 SQL Editor에서 운영 스키마 SQL을 번호 순서대로 실행합니다. **001–014를 적용하고 015는 건너뛴 뒤 016–037을 적용**합니다.

!!! danger "015는 데모 전용"
    `015_seed_customer_demo.sql`은 테스트 조직에 가짜 고객·시술·사진 메타데이터를 만드는 선택적 데모 데이터입니다. 개발자가 격리된 데모 DB를 명시적으로 준비할 때만 사용하고, 운영·실고객 환경에는 실행하지 않습니다.

| 구간 | 주요 내용 |
| --- | --- |
| 001–004 | 인증, 조직, 구독과 관리자 RPC |
| 005–014 | 고객, 업무, 문서, 재무, 파일과 활동 |
| 015 | 선택적 데모 시드 · 운영 적용 제외 |
| 016–023 | 시술, 상담, 문서 버전·발행·동의, 고객 사진과 Storage |
| 024–026 | 방문 장바구니, 수납과 기존 DB 보강 |
| 027–029 | 상품·회원권, 사용 원장과 환불·취소 |
| 030–033 | 재고 조정, 상품 반품, 할인, 일 마감·미수 |
| 034–036 | 예약, 회원권 정지·재개·연장, 운영 수지 근거 |
| 037 | 예약 담당자 근무시간·휴무와 예약 충돌 차단 |

각 파일이 성공한 뒤 다음 번호를 실행합니다. 015를 건너뛰어도 016부터 정상 적용할 수 있습니다. 중간 오류가 발생하면 다음 파일로 넘어가지 말고 오류를 해결합니다.

## 기존 프로젝트 업그레이드

이미 적용한 파일은 다시 실행하지 않습니다. 마지막으로 적용한 번호 다음부터 실행합니다.

- 024까지만 적용: **025 → 026 → 027 → 028 → 029**
- 026까지 적용: **027 → 028 → 029**
- 028까지 적용: **029**
- 030까지 적용: **031 → 032 → 033**
- 033까지 적용: **034 → 035 → 036 → 037**
- 036까지 적용: **037**

적용 후 서버와 데스크톱 앱을 같은 소스 버전으로 재시작합니다. 세부 변경은 [저장소의 마이그레이션 안내](https://github.com/MyungSungKim12/business-assistant/blob/main/migrations/README.md)를 확인합니다.

## 환경변수

| 변수 | 사용 위치 | 설명 |
| --- | --- | --- |
| `APP_API_BASE_URL` | 데스크톱 | FastAPI 서버 주소 |
| `APP_FILE_BUCKET` | 서버 | 비공개 파일·사진 버킷 이름 |
| `APP_SUPABASE_URL` | 서버 | 프로젝트 URL |
| `APP_SUPABASE_PUBLISHABLE_KEY` | 인증 흐름 | 공개 가능한 프로젝트 키 |
| `APP_SUPABASE_SERVICE_KEY` | 서버 전용 | Storage와 서버 작업용 비밀키 |
| `APP_DATABASE_URL` | 서버·DB 테스트 | 직접 DB 연결이 필요한 경우 |

## 사진과 파일 Storage

`023_customer_photo_storage_bucket.sql`은 고객 사진 저장 정책을 보강합니다. 버킷 이름은 기본적으로 `business-files`이며 `.env`의 `APP_FILE_BUCKET`과 일치해야 합니다. 서비스 키는 서버 프로세스에만 제공하고 데스크톱 배포 파일에 포함하지 않습니다.

## 적용 후 확인

1. 서버를 실행해 `/health` 응답을 확인합니다.
2. 로그인하고 조직 목록을 불러옵니다.
3. 테스트 고객으로 조회·수정 권한을 확인합니다.
4. 사진 한 장을 등록하고 다시 조회합니다.
5. 상품과 회원권 목록을 엽니다.
6. 테스트 방문에서 수납·환불 흐름을 확인합니다.
7. 다른 조직 사용자가 해당 데이터를 읽을 수 없는지 확인합니다.
8. 예약 담당자·서비스 등록, 중복 시간 거절, 방문 장바구니 생성과 회원권 정지/재개를 확인합니다.

!!! warning "운영 데이터"
    운영 DB에서 테스트하려면 전용 테스트 고객과 명확한 사유를 사용합니다. 실제 고객에게 임의 사진, 잔액이나 가공한 활동 기록을 만들지 않습니다.
