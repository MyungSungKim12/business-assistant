# 권한·보안·운영 점검

## 권한의 두 단계

Business Assistant는 화면 표시와 서버 검사를 함께 사용합니다.

1. **기능 권한**: 구독에 포함된 기능 코드로 메뉴 접근을 결정합니다.
2. **조직 역할**: owner, admin, member 역할로 조회·변경 범위를 제한합니다.

메뉴가 보인다는 사실만으로 변경 권한이 생기지 않습니다. 모든 API가 access token, 조직 멤버십, 역할과 기능 권한을 다시 확인합니다.

## 역할별 기본 원칙

| 작업 | owner/admin | member |
| --- | --- | --- |
| 조직 업무 데이터 조회 | 허용된 기능에서 가능 | 허용된 기능에서 가능 |
| 고객·시술 등 관리 변경 | 가능 | 화면별 정책에 따라 읽기 전용일 수 있음 |
| 서식·카탈로그 관리 | 가능 | 제한 |
| 다른 조직 데이터 접근 | 불가 | 불가 |
| 서비스 키 사용 | 서버만 | 서버만 |

## 매일 확인

- 서버 로그에 반복되는 401, 403, 503이 없는지 확인합니다.
- 결과 미확인 수납·환불이 남아 있지 않은지 확인합니다.
- 오늘 완료된 수납과 재무 수입 합계의 차이를 확인합니다.
- 사진·파일 업로드 실패가 반복되지 않는지 확인합니다.

## 정기 확인

- Supabase 백업과 복원 가능 시점을 확인합니다.
- 조직별 직원 계정과 퇴사자 접근을 정리합니다.
- 서비스 키와 관리자 계정을 교체·점검합니다.
- RLS와 서버 권한 회귀 테스트를 실행합니다.
- 보관 데이터와 영구 삭제 요청을 구분해 처리합니다.

## 로그에 남기지 않을 정보

비밀번호, access token, service key, 전체 카드 정보와 불필요한 고객 민감정보를 로그에 남기지 않습니다. 장애 조사에는 요청 ID, 기능, 상태 코드와 안전하게 마스킹한 식별자만 사용합니다.
