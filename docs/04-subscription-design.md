# 구독과 기능 권한 설계

## 핵심 용어

- **Plan(상품)**: BASIC, STANDARD, PRO처럼 판매하는 구독 묶음입니다.
- **Feature(기능)**: `crm.basic`처럼 한 가지 권한을 나타내는 코드입니다.
- **Subscription(구독)**: 한 조직이 어떤 상품을 언제까지 이용하는지 기록합니다.
- **Entitlement(최종 권한)**: 현재 시점의 상품, 기간, 상태, 관리자 부여를 계산한 실제 사용 가능 기능 목록입니다.

상품은 여러 기능을 포함하고, 한 조직의 구독은 상품과 시작·만료 시각을 가집니다. 서버가 이 정보를 계산해 entitlement를 만들며, 데스크톱은 그 결과를 메뉴 표시에만 사용합니다. 보호된 API는 서버가 entitlement를 다시 검사합니다.

## 만료와 기기 제한

만료 시각이 지나거나 구독이 취소·정지되면 유료 entitlement는 즉시 사용할 수 없게 합니다. 항상 열려 있는 기본 메뉴는 유지하되, 유료 작업을 요청하면 `SUBSCRIPTION_EXPIRED` 같은 오류 코드로 갱신 또는 관리자 문의를 안내합니다. 권한 응답은 짧게 캐시할 수 있지만 구독 변경과 환불 뒤에는 서버 판단을 우선합니다.

조직별 상품에는 허용 기기 수를 둘 수 있습니다. 새 PC를 등록할 때 서버가 활성 기기 수와 조직 권한을 확인합니다. 한도를 넘으면 사용자에게 기존 기기 해제 또는 상품 변경을 안내하며, 기기 등록·해제는 감사 로그에 남깁니다.

## 초기 수동 부여

결제 연동 전에는 관리자 명령이나 테스트 픽스처로 조직에 제한된 기간의 구독을 부여합니다. 수동 부여에는 대상 조직, 상품, 시작·종료 시각, 사유, 작업자를 남기고 권한 캐시를 무효화합니다. 이 방식은 개발과 고객 온보딩에만 쓰며 임의의 클라이언트 요청으로 실행하지 않습니다.

## 결제 웹훅 준비

결제대행사를 연결하면 웹훅 서명을 공급자별 비밀키로 검증합니다. 이벤트 ID를 저장해 같은 이벤트가 여러 번 와도 한 번만 처리하는 idempotency를 보장합니다. 검증이 끝난 이벤트만 구독을 바꾸고, 결과와 추적 ID를 감사 로그에 기록합니다. 서명값, 원문 결제 정보, 비밀키는 로그에 남기지 않습니다.
