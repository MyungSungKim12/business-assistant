# F16 예약 가능 시간 조회 묶음화

기능 APT-015/APT-12, 감사 F16. 상태 in-progress. 다음 우선순위 구현 승인. 기존 화면·순수 슬롯 계산·저장 시 DB 최종 검사를 유지한다. 추가 SQL 없음.

1. 직원별 getStaffAvailability(직원 재조회+근무+휴무)를 직원 UUID 50명 묶음의 근무/휴무 2개 조회로 교체한다. 조직/직원·중복·status·count/범위를 검증한다. 응답 누락을 ‘근무 제한 없음’으로 해석하지 않는다. 기존 Rest.selectAll의 완전 조회를 재사용한다.
2. 휴무는 선택일 KST 0시부터 다다음날 0시까지 겹치는 active만 조회한다. 서로 다른 근무 시간대에서 자정을 넘는 후보의 소요/여유도 포함한다. 예약도 전날~다음날을 읽어 자정 이후 충돌을 놓치지 않는다.
3. API 권한·자원·서비스 담당 제한은 유지한다. 직원 10명/100명 HTTP 호출 수와 기존 슬롯 규칙을 검증한다. 직원 2,000명 초과는 명시 실패하고 담당자 지정 조회를 사용하도록 한계를 기록한다.
4. 클라이언트 입력 변경은 250ms debounce, 이전 요청 결과 무시와 키별 미확인 상태 처리. 캐시는 두지 않아 다른 PC 변경·저장 후 무효화 문제를 피한다. IPC 실제 취소는 이번 범위가 아니다.
5. 집중 API·React·타입 검사·독립 리뷰 후 제품 기록 갱신. 실제 앱·운영 DB·전체 테스트·커밋 없음.

2026-10-20 마무리: API 91개·React 69개·양쪽 타입 검사 통과. 리뷰의 기존 짧은 페이지 종료로 인한 충돌 누락을 재현·수정해 공유 목록도 count 검증으로 전환했다. 같은 조건 재확인과 응답 service/date 대조를 포함했다. 추가 SQL·실앱·운영 DB·전체 테스트·커밋 없음. [제품 기록](../../product/audits/2026-10-20-availability-batch.md).
