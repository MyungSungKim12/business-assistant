# 2026-10-06 장바구니 안정화·수납 연결 계획

사용자의 전체 진행 요청에 따라 기존 SALE-001 계획의 잔여 안정화와 SALE-002 최소 실업무 동선을 순서대로 구현한다. 기존 변경을 보존하며 커밋/운영 데이터 변경은 하지 않는다.

1. SALE-001 DB: 엄격한 입력, 재시도 사용자 일치, 잠금 순서, 검토 상태 재설정, 원자적 조회와 격리 DB 회귀.
2. SALE-001 서버: 단일 RPC 조회, 엄격한 API 입력, 문서 편집 권한 없이 허용된 결제 초안 조회, API/저장소 테스트.
3. SALE-002: 현금/카드/이체의 외부 수납 확인 기록과 부분 수금. 단말기 승인 요청을 보내는 기능과 구분한다. 원 단위 KRW 정책, 불변 청구 스냅샷, 복합 수단, 과수금 방지, 동일 요청 재시도, 조직/역할/버전 검증. 수납 시작 시 장바구니 편집 잠금. 지갑은 WAL 선행 원장 완성 전 비활성.
4. 수납 서버/클라이언트/Qt 화면과 실패·재시도·권한 테스트, 적용 문서.
5. 전체 검증 가능한 범위 실행 및 독립 리뷰. 실환경·외부 단말기 연동은 미검증으로 명시.

금융 계약이 없는 환불/세금/쿠폰/재고 수당 처리를 임의 확정하지 않는다. SALE-003 이후 제품 범위는 로드맵에 유지한다. 현재 작업의 '전부'는 직전 제시한 안정화→복합수납·부분수금 전체 흐름이다.
