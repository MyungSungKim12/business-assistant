# F12 대량 목록 완전성 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

기능: INV-11 / FILE-11, 감사 F12. 사용자 승인 범위: 다음 우선순위 계속 구현. 기존 작업 트리를 보존하고 새 SQL·실환경 접속·전체 테스트·앱 실행·커밋은 하지 않는다. 061 사용자 적용 보고를 기록한다.

설계: 기존 배열 API와 화면을 유지한다. 공통 Rest.selectAll은 Prefer count=exact, limit/offset, Content-Range 검증을 사용한다. 짧은 응답 길이를 마지막 페이지로 추측하지 않는다. 동일 정렬값은 id로 구분한다. 매 페이지 조직 필터·토큰 유지, 중복 ID·잘못된 범위·총건수 변경·중간 실패는 전체 실패다. 최대 20,000행/100페이지/30초의 제한을 넘으면 503으로 거절한다. 이는 한 번에 불러오는 현재 화면의 안전장치이며 무제한 목록이나 DB 스냅샷을 보장하지 않는다.

- [x] 공통 페이지 수집 계약 테스트를 먼저 실패로 확인한다. 서버 한도가 요청 크기보다 작은 경우, 정확한 빈 목록, 중간 오류, 건수·범위·중복·상한 검증을 포함한다.
- [x] 공통 selectAll을 구현하고 발주서/품목/공급처 및 파일/폴더 목록에 적용한다. 발주 품목은 주문 ID를 Map으로 결합하고 부모 없는 품목은 실패시킨다.
- [x] 모듈 HTTP 테스트에서 다중 페이지·조직 경계·중간 실패·기존 권한과 보관 필터를 확인한다. 관련 테스트와 타입 검사만 실행한다.
- [x] 독립 리뷰와 제품 기록을 갱신한다. 실환경 미검증·동시 변경 시 스냅샷 한계·상한 초과의 서버 페이지 UI 전환 필요를 명시한다.

완료 기록: API 100개/React 17개/양쪽 타입 검사 통과, 독립 리뷰 중요 지적 없음. 제품 기록에 적용 대상과 동시 변경·상한·실환경 제한을 명시했다.
