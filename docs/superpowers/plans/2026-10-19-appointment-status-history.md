# F13 예약 상태 변경 이력

기능 APT-003/019, 감사 F13. 승인: 다음 우선순위 구현. 상태 in-progress. React/Node/Supabase 유지, 기존 작업 트리 보존.

- SQL 062: no_show_reason 추가, 조직·예약 FK와 상태/버전/사유 제약의 불변 이벤트 테이블. 인증 조직 구성원 SELECT RLS, 클라이언트 DML 거절. 기존 transition RPC만 교체하여 상태/사유/이력을 원자 기록하고 operation_id 재실행은 기존 스냅샷 반환. 기존 충돌/권한/방문·장바구니 생성은 보존.
- 읽기 RPC: 조직/예약 확인 후 해당 상태 이벤트만 버전순 반환. 이벤트에 시각·변경자 UUID·전후 상태·예약 버전. 과거 이력 가공/복원 없음.
- API: 기존 task.basic 권한 유지. 조직/예약/중복/순서 검증, 취소/노쇼 빈 사유 거절.
- React: 예약 상세에 별도 이력 조회 컴포넌트. 실패/미적용/빈 기록 구분·재시도·늦은 응답 차단, 상태 변경 후 버전 기준 갱신. 기존 레이아웃/스타일은 유지. 노쇼 사유는 취소와 구분.
- 선행 실패 확인 후 격리 DB·API·React 집중 검증 및 타입 검사. 독립 리뷰·제품 기록. 전체 테스트·실앱·원격 DB·커밋/푸시 없음.

관리자 상태 정정/슬롯 재점유 정책은 이번 범위가 아니다. 완료·취소·노쇼의 기존 전이 제한을 완화하지 않는다. SQL 062 실행은 사용자 후속 단계다.
