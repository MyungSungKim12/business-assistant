# INV-11 공급처·발주·입고 구현 계획

## 범위
공급처 관리(담당자·연락처·이메일·메모), 여러 품목을 포함한 발주서 초안·발주·취소, 부분 입고, 실제 입고분의 상품 재고 및 불변 원장 반영. 바코드 장비, 유통기한·로트, 카테고리, 상품 이미지 및 세금계산서 연동은 다음 범위다.

## 제약과 검토 초점
기존 catalog_products와 catalog_stock_ledger를 재사용한다. 발주 변경과 입고는 서버 원자 RPC로 처리하고 operation_id로 재시도 안전성을 보장한다. 입고 수량은 잔여 발주량을 초과할 수 없으며 취소된 발주는 입고할 수 없다. 주문·공급처·상품 FK는 조직 composite key로 격리한다.

## 작업 순서 (TDD)
1. 격리 DB 시나리오를 추가해 발주 상태, 부분/완료 입고, 초과 입고, 재시도, 동시성·조직 격리, 재고 원장 반영을 먼저 고정한다.
2. catalog API 테스트에 공급처/발주 CRUD 및 입고 endpoint의 유효성·권한·오류 검증을 추가한다.
3. migration 058에 공급처, 발주/품목/입고 원장, RLS와 멱등 RPC를 추가하고 PGlite 검증을 수행한다.
4. catalog gateway/routes/schema를 확장하고 API 테스트를 통과시킨다.
5. InventoryPage에서 공급처 상세정보와 동적 다품목 발주 입력·삭제, 부분입고 UI를 연결하고 화면 테스트를 추가한다.
6. backlog, 재고·구매 문서, changelog, migration README에 상태와 실환경 제한을 기록한다.

## 완료 조건
입고가 발주잔량·상품 재고·재고 원장을 한 트랜잭션으로 일치시키며, UI가 여러 품목을 한 발주로 전송한다. 검증은 발주 API 격리 DB 테스트와 화면/API 집중 테스트로 확인한다. 로트·유통기한 기능은 구매 입고와 일반 입고가 같은 lot 원장으로 일치하는 추가 설계를 끝낸 뒤 별도 마이그레이션으로 진행한다. 실 Supabase 적용은 사용자 작업으로 남는다.
