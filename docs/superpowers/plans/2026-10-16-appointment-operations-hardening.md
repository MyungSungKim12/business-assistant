# 예약 화면 상세 및 운영 안전성 보완

기준: 2026-10-16 신규 소스 감사 F01–F08. 사용자 구현 승인 범위에서 현재 작업 트리를 보존한다. 원격 DB 적용·전체 테스트·앱 실행·커밋은 하지 않는다.

## 실행 순서

1. APT-005: 대기 예약 RPC 응답의 중첩 조직 검증, 구성원의 예약/대기 권한 일치, APT-002/015: 담당 가능 직원만 빈 시간 안내. 실제 게이트웨이 회귀 검증.
2. CRM 입력 보호: 저장 실패 후 dirty 유지. 예약/고객 입력·메모와 메뉴 이동/로그아웃의 보호 연결.
3. INV-11: 응답 유실 시 동일 입고 요청 ID 재사용, 미확인 처리 보존 및 중복 발주 억제. 입고 수량을 앱 폼에서 입력.
4. SEC-STORAGE: SQL 060으로 보관 사진·파일의 직접 Storage 읽기 차단, 조직/원장 경로 일치 확인. 격리 DB 권한 행렬 검증.
5. APT-001/003: 예약 새로고침·최근 동기화·상태 요약·필터·고객 검색, 자동 갱신과 작성 내용 보호. 기존 베이지 구조 유지.
6. 변경 범위의 타입 검사 및 집중 테스트, 감사 후속 기록과 SQL 적용 안내.

## 검증 및 기록

구현 전 기존 재현 스크립트를 올바른 동작을 기대하는 회귀 검사로 전환해 실패를 확인한다. 이후 수정한 범위만 검사한다. 기존 감사 보고서는 삭제하지 않고 후속 결과를 추가한다. 검증하지 않은 실환경·추가 확장 기능은 완료로 표시하지 않는다.

## 진행 원장

- 시작: 계획 수립, 관련 APT 기능은 기존 in-progress 유지. Supabase SQL은 원격에 적용하지 않는다.
- 범위 판단: 새 예약 채널·방문/결제 통합·고객 지표 재정의 등 F09 이후의 독립 확장 기능은 이번 보안 및 예약 상세 보완의 완료 조건과 분리한다.

- 단계 1 완료: 실제 게이트웨이 정상/조직 불일치, member 대기 등록, 담당 가능 직원 회귀 통과. API 집중 검사 31건.
- 단계 2 완료(주요 화면 범위): 고객 실패 dirty 보존, 공통 DraftBoundary 합산, 메뉴/검색/로그아웃/트레이/브라우저 보호. 부가 팝업 전수·Native 종료는 후속.
- 단계 3 완료(코드): 발주·입고 복구 요청을 사용자·매장별 보관, 결과 미확인 시 신규 입력 차단, 팝업 재개 후 같은 operation ID 재확인. 실사 하단도 보호 연결.
- 단계 4 완료(준비·격리 검증): SQL 060 반복 적용·권한 행렬 통과. 원격 미적용; SEC-12는 in-progress 유지.
- 단계 5 완료(코드): 예약 상태/담당 필터·상태 건수·검색·종료 예상·갱신 추가. 편집 버전 고정, 늦은 응답 무시, 조회 기간에서 사라진 선택 예약 snapshot 보존.
- 단계 6 완료: React 184+2건 및 API 31건, 타입 검사, DB Storage/예약/발주 검사, git diff --check 통과. 소스 검토에서 발견한 문제를 RED→GREEN으로 수정. 상세 명령과 제한은 제품 후속 보고서에 기록.
- 실행 범위 판단: 원격 DB·실제 앱·전체 테스트·커밋/푸시는 사용자 기존 범위에 따라 미실행. F09 이후 독립 확장과 F16 대량 조회 최적화는 미완료로 남김.
