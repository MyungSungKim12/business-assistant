# 매출·지출 관리 모듈 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 조직별 수입·지출 거래 원장과 기간별 합계 API를 `finance.basic` 권한으로 제공한다.

**Architecture:** FastAPI 재무 라우터가 JWT·조직 멤버십·구독 권한을 확인하고, 현재 사용자 JWT를 전달받은 PostgREST 어댑터에 거래 CRUD와 기간 조회를 위임한다. Supabase migration은 `numeric(14,2)` 금액, 거래 유형·날짜 제약, 조직별 RLS와 테넌트 불변 트리거를 정의한다.

**Tech Stack:** Python 3.13, FastAPI, Pydantic v2, `Decimal`, `datetime.date`, httpx, Supabase PostgREST, PostgreSQL RLS, pytest.

**Spec:** `docs/superpowers/specs/2026-09-16-finance-design.md`

## Global Constraints

- `finance.basic`가 없는 구독은 API에서 403을 반환한다.
- 조직 멤버십이 없는 사용자는 거래와 집계를 확인할 수 없다.
- 모든 거래 데이터는 `organization_id`로 분리하고 RLS를 활성화한다.
- SELECT는 owner/admin/member, INSERT/UPDATE는 owner/admin만 허용한다.
- `organization_id`와 `created_by`는 UPDATE에서 변경할 수 없다.
- 금액은 `numeric(14, 2)`로 저장하고 0보다 커야 한다.
- 물리 삭제는 제공하지 않고 `is_archived`로 보관한다.
- Supabase publishable key와 현재 사용자 JWT만 사용한다.
