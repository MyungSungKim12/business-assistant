# CRM-014 고객 보유·영구 파기 구현 계획

## 목적

사용자가 승인한 조직별 보유기간·명시적 관계 종료·법적 보류·관리자 확인 원칙을 DB에서 강제한다. 기간 기본값은 두지 않으며, 첫 단계에서는 최종 파기를 실행하지 않는다.

## 작업 단계

1. **계약/회귀 테스트**: PGlite에서 정책 테이블, 조직/역할 경계, 버전 검사, 미설정 기간, 관계 종료, 보류 이력과 감사 이벤트를 검증한다. 구현 전 테스트가 실패하는지 확인한다.
2. **DB migration**: CRM-014 정책/보류/이력 테이블, RLS, 관리자 전용 SECURITY DEFINER RPC와 권한 제한을 추가한다. 누락 기간과 활성 보류를 안전하게 거부한다.
3. **API 연결**: `crm.basic` 관리자 검사와 입력 스키마를 적용해 정책 읽기/수정, 관계 종료·재개, 보류·해제를 노출한다. 조직 ID는 경로에서만 받는다.
4. **UI/운영 안내**: 고객관리 설정에서 기간 미설정 경고, 기간 입력, 관계 종료/재개, 보류 상태·사유를 제공한다. 최종 삭제 버튼은 보이지 않으며, 파기 설계 미완료 상태를 분명히 알린다.
5. **문서/검증**: 기능 문서, D-10, backlog, changelog를 갱신한다. 집중 DB/API/React 테스트와 빌드를 실행하고, 실환경 검증 미수행을 기록한다.

## 검증 기준

- 권한 없음/다른 조직/잘못된 입력/오래된 버전/중복 재시도/보류 생성·해제 기록을 시험한다.
- 미설정 기간과 열린 보류에서 파기 가능으로 오인되는 결과가 나오지 않는다.
- 원격 Supabase에는 SQL을 적용하지 않고 사용자가 실행할 신규 migration 순서를 문서화한다.

## 범위 밖

실제 DB 레코드·Storage 파일 삭제, 백업 파기, 법률 기간 값 추천, Supabase 원격 적용, 커밋/푸시.
