# 예약에서 고객·시술·수납으로 연결

승인 근거: 사용자 다음 우선순위 진행 요청. 기존 감사 F09 및 APT-004/Sale 방문 장바구니 범위. 기존 React/Tauri·Node API와 화면 구조를 사용한다.

1. SQL 060 사용자 적용 보고를 기록한다. 원격 확인·실데이터 변경·전체 테스트·커밋은 하지 않는다.
2. 예약 상세에서 고객·시술 고객 이력으로 이동하고, 방문 처리/완료 건은 동일 예약의 기존 방문 장바구니로 이동한다. 공통 이탈 보호를 통과하며 매출 기능 권한이 없으면 수납 진입은 숨긴다.
3. 예약 ID+고객 ID로 기존 방문을 조회하는 읽기 필터를 추가한다. 일치 없음/중복/오류는 명시하고 방문 자동 생성으로 대체하지 않는다. 조직·고객·예약·장바구니 연결이 다르면 거절한다.
4. 시술 화면에서 요청 고객이 없으면 다른 고객을 대신 선택하지 않는다. 시술 기록 생성·시술 청구 초안 담기는 사용자의 기존 명시 동선을 유지한다.
5. API·React 집중 테스트와 타입 검사 후 문서를 갱신한다. 새 SQL은 필요하지 않다.

상태: in-progress. 예약과 시술 원장의 별도 방문 FK 도입, 자동 청구 생성·확정, 수납 자동 기록은 이번 변경 범위 밖이다.
