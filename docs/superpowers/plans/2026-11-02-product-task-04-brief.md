# N1030-04 / INT-007 영속 전화 수신함 요구사항

상위 설계의 4번을 앞선 1~3번 검증/SQL 적용 뒤 순차 구현한다. 기존 실제 동작하는 Android→PC 독립 알림/요약/메모를 유지하면서 내구성과 응대 이력을 연결한다. 현재 서버는 `modules/phone/incoming-calls.ts`의 단일 프로세스 CallRelayStore, 2분 TTL, org+user별 채널/cursor와 8초 long poll이다.

## 결정·경계

- 원격 SQL 번호는 직전 작업을 보고 확정한다(예상104). DB 저장 기반 relay + 이력으로 서버 재시작/다중 API에서도 같은 이벤트/cursor를 조회한다. 메모리 wake-up은 단일 인스턴스 최적화일 뿐 진실이 되어서는 안 된다.
- 기존 PC 전달은 **같은 계정·매장**을 유지한다. 전 직원에 자동 방송하지 않는다. 인박스는 본인이 받은/명시적으로 배정받은 기록만 기본 허용하고 배정은 같은 조직의 활성 구성원인지 검증한다.
- Android가 보내는 실제 수신 정보는 number/occurred_at/event_id뿐이다. 서버가 정확 일치한 active/vip 고객만 저장하고 arbitrary matches/user_id/name/organization을 클라이언트가 주입하게 하지 않는다.
- **전화가 왔다는 사실과 실제 부재중/통화 종료는 다르다.** 현재 OS 이벤트에 종료/응답 사실이 없으면 '미확인/확인/응대 완료/콜백 필요'로 표현한다. 2분 알림 만료를 실제 부재중 통화로 위조하지 않는다.
- 동일 event ID 재전송은 같은 번호/시각이면 멱등, 내용이 다르면 충돌. 원격 sequence/cursor는 안정적인 조직/수신자 범위이며 다른 조직 cursor/이전 메모리 cursor도 오류/초기화 규칙을 명시한다. 리스트 limit/cursor와 동시 요청·listener 수를 제한한다.

## 보유·동의 (구현자 결정)

- 기존 Android의 동의는 실시간 PC 전송 목적이므로 기존 APK에는 2분 알림 저장·복구만 제공한다. 장기 응대 이력을 묵시적으로 켜지 않는다.
- 새 APK에 선택적인 **수신 기록 보관 동의**와 보유기간 안내를 추가한다. 기본 꺼짐, 기존 consent와 분리/버전 관리. 실제 동의한 요청만 장기 이력에 남기며 초기 기본 보유기간은 30일로 한다. 서버는 수신자 자신의 기록 동의만 반영한다. PC 설정/인박스에도 상태를 표시한다.
- 번호부/PC 동의 철회·로그아웃·매장 전환은 기기 큐와 진행 중 수신 요청을 무효화한다. 서버 동의 철회 이후 새 이력 저장을 거절/실시간 범위로 제한하고 기존 이력 정리는 보유정책에 따라 명시한다.
- 원문 번호는 업무 조회 범위/RLS로 보호하고 표시에는 maskPhone을 사용한다. 이름/프로필 메모·사진을 영속 call history에 무제한 복제하지 않는다. 고객 식별자·실제 수신 시각·원문 번호·처리 상태 같은 필요한 사실만 저장한다.
- 만료 이벤트/이력은 조회에서 즉시 제외하고, 제한된 내부 정리 함수(또는 뒤의 유지보수 주기와 연결)로 제거한다. 실제 고객 활동/시술/매출 원장은 정리 대상이 아니다.

## 사용자 동선

1. 기존 더보기/고객 메뉴 패턴에 전화 수신함 진입점을 추가한다. 화면 전체 재디자인 없이 날짜/고객·상태 필터, 페이지, 오류·재시도·읽기 권한 표시.
2. 수신 기록→고객 상세/응대 요약→메모 저장·응대 완료·콜백 할 일·담당자 배정을 연결한다. 메모·상태는 버전/operation ID, 실패 입력/이탈 보호. 다른 사람이 먼저 처리하면 충돌로 갱신 안내한다.
3. 콜백 할 일 생성은 동일 작업 재시도로 중복되지 않고 기존 tasks의 고객/기한·권한 계약을 사용한다. 실행했다고 통화 완료를 임의 기록하지 않는다.
4. 네이티브 알림의 고객/메모 수락 후 닫기 ACK를 보존한다. 카드 열기는 '확인', 실제 응대 완료는 사용자 저장/명시적 행동으로 구분한다. 알림이 사라져도 동의한 수신함 기록은 남는다.
5. 기존 매칭된 번호의 수동 메모 API와 S23 연락처 권한 동작을 깨지 않는다. 이력 메모는 저장된 매칭 customer_id/조직을 근거로 하며 당시 전화와 현재 연락처가 바뀐 경우를 구분해 검증한다.

## 검증/전달

실패 재현 후 집중 API/React/Kotlin/격리 SQL 검증: 2개 gateway/프로세스 사이 publish/poll, 서버 재생성, cursor 재시도/중복/충돌, 다른 조직/계정·동의 없는 장기 이력 거부, 배정·활동/할 일 중복 방지, TTL과 실제 응대 사실 구분, 입력 보호.

전체 테스트·실제 앱/전화·실사용 데이터 변경·원격 SQL·커밋/푸시 금지. parent가 SQL을 검토/적용한다. 예상 변경은 phone DB gateway/routes, 기존 mobile relay/Android consent, React 수신함/API/메뉴·PhoneMemoDialog 연결이다. 다른 작업의 파일을 무단 리셋하지 않는다. 보고서 `docs/product/audits/2026-11-02-durable-phone-inbox.md`에 SQL/RPC·동의/보유·환경·변경 파일·명령/결과·한계를 기록한다.
