# F10 / CRM-011 방문·예약 사실 요약

사용자 승인: 남은 우선순위를 계속 구현. 기존 React/Node/Supabase를 유지하고 고객 수기 필드를 변경하지 않는다.

- 실제 최근 방문: 취소되지 않은 방문 원장의 opened_at(KST 날짜), 완료된 시술의 treatment_date 중 최근 값. 미래 원장은 제외한다. 환불은 방문 사실을 지우지 않는다.
- 다음 예약: reserved/confirmed이며 시작 시간이 현재 이후인 가장 이른 예약. 취소·노쇼·이미 방문한 예약·재방문 권장일은 포함하지 않는다.
- 재방문 권장: 가장 최근 완료 시술의 next_visit_date. 실제 예약과 별도 표시한다.
- 읽기 전용 SQL 061 RPC로 고객 ID 200개 이내 배치 계산, 조직·역할·RLS 검증. 고객별 N+1 조회·프로필 일괄 덮어쓰기는 하지 않는다.
- CRM 인사이트와 홈의 최근/다음 방문 패널을 실제 요약으로 연결하고 조회 실패/SQL 미적용은 미확인으로 표시한다. 수기 날짜를 실제 사실로 대체 사용하지 않는다.
- 집중 API/React/격리 DB 검사 후 SQL 적용 안내와 상태 기록. 실제 앱·전체 테스트·원격 적용·커밋은 하지 않는다.

진행: in-progress. 실제 방문 원장 전수 정리·이전 수기 데이터 자동 변환은 범위 밖이다.
