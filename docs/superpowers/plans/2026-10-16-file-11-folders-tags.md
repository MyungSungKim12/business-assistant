# FILE-11 파일 폴더·태그 구현 계획

## 범위
저장된 파일 레코드에 조직별 폴더와 태그 메타데이터를 붙이고 검색·필터·관리한다. 파일명·태그를 함께 검색하고, 폴더 삭제 시 포함 파일은 미분류로 옮기되 파일 자체는 보존한다. Storage object 경로는 바꾸지 않는다. 공유 링크, 용량 한도, 버전 관리는 제외한다.

## 제약과 검토 초점
기존 `files.basic` 접근제어와 file_assets를 유지한다. 모든 폴더·파일 연결은 organization_id 복합 외래키로 격리한다. 태그는 최대 10개, 요청에서 공백 제거와 중복 제거를 한다. 신규 파일은 업로드 후 폴더·태그를 지정한다(업로드 중 분류 선택은 후속).

## 작업 순서 (TDD)
1. 문서 API 테스트에 폴더 목록/생성/삭제와 파일 메타데이터 업데이트의 검증·권한·조직 범위 케이스를 추가한다.
2. migration 057에 file_folders와 file_assets.folder_id/tags, RLS 정책, 조직 검증 RPC/제약을 추가하고 기존 행 호환성 테스트를 작성한다.
3. documents gateway/routes/schema를 확장하고 테스트를 통과시킨다.
4. FilePage에 폴더·태그 등록, 필터, 파일 분류 변경 UI를 연결하고 화면 테스트를 추가한다.
5. FILE-11 상태·제한을 backlog, 파일 문서, changelog, migration README에 기록한다.

## 완료 조건
기존 파일/업로드/다운로드 동작을 보존하며, 조직 분리와 멤버/관리자 권한이 검증되고 SQL 적용 필요성을 문서화한다.
