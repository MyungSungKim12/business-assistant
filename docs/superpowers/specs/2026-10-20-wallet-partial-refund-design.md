# WAL-11 회원권 금액권 부분 환불 설계

## 목표

관리자가 고객과 합의하고 외부 환불을 실제 완료한 뒤, 사용하지 않은 금액권 잔액의 일부 또는 전부를 시스템에 기록할 수 있게 한다. 환불 기록, 회원권 잔액, 재무 지출, 수당 조정이 하나의 원자적 DB 작업으로 일치해야 한다.

## 기본 결정

- 관리자는 외부 결제 수단에서 환불을 완료한 다음 환불액을 앱에 기록한다. 앱은 카드사·은행·현금 이동을 실행하지 않는다.
- 환불액은 관리자가 입력한 실제 환불액이며 양수 원 단위다. 이 기능은 계약 해지 수수료나 잔여 서비스의 법정 환급액을 산정하지 않는다.
- 금액 혜택만 있는 회원권에 한해 환불액만큼 금액 잔액을 줄인다. 횟수 혜택이 있거나, 발급된 금액 혜택과 할인 후 판매 금액이 다르거나, 이미 만료/정지된 경우는 이번 경로를 허용하지 않는다. 이는 보너스·혼합 혜택의 환급 가치를 추정하지 않기 위함이다.
- 환불액은 현재 잔액 및 해당 회원권에 귀속된 실제 결제액에서 이전 환불액을 뺀 금액을 초과할 수 없다. 할인 후 판매액과 발급 금액이 1:1인 금액권은 사용액과 잔액이 같은 원 단위로 대응한다.
- 부분 환불 후 남은 잔액은 활성 상태로 남는다. 잔액이 0이면 회원권은 `refunded` 상태가 되어 추가 사용·양도·수명주기 변경을 할 수 없다.
- 환불은 현재 서울 날짜의 재무 지출 `Membership refund`로 기록한다. 월 마감된 날짜에는 기존 재무 마감 트리거가 차단한다.
- 환불 수당 조정은 환불 발생일에 유효한 회원권 수당 규칙을 사용해 음수 거래로 기록한다. 과거 확정 정산은 수정하지 않는다. 확정된 수당 기간과 겹치면 환불 기록을 거절해 과거 원장을 덮어쓰지 않는다.
- 모든 변경은 owner/admin 전용, 조직 범위, 잔액 버전, 멱등 operation ID, 불변 원장 및 사유를 요구한다.

## 제외 범위

횟수권·혼합 혜택·보너스 금액·할인 판매의 자동 환급 계산, 위약금/수수료 계산, 외부 결제 취소, 확정 수당 기간 재개방 및 급여 지급은 포함하지 않는다. 필요하면 별도 정책과 원장 설계 후 추가한다.

## 사용자 흐름

1. 고객 회원권 화면에서 활성 금액권을 고르고 `환불 기록`을 연다.
2. 서버 미리보기에서 원 구매금액, 환불 가능 상한, 현재 잔액, 잔액 버전을 조회한다.
3. 관리자는 외부 환불을 완료한 후 환불액과 사유를 입력한다.
4. 확인 팝업은 외부 환불은 이미 완료됐으며 앱에는 잔액·재무·수당 기록만 저장된다는 점을 표시한다.
5. 서버는 원 구매/혜택 1:1 여부, 조직·권한·버전·마감·정산 중복·금액 상한을 다시 검사한 뒤 잔액, 환불 원장, 재무 거래를 함께 저장한다.
6. 같은 operation ID와 같은 요청을 재시도하면 같은 결과를 돌려준다. 같은 ID로 다른 입력을 보내면 충돌을 반환한다.

## 검증 기준

- 정상 부분 환불, 잔액 0이 되는 전액 잔액 환불, 재시도는 한 번만 반영된다.
- 금액 초과, 버전 충돌, 수당 기간 확정과 충돌, 마감 월, 할인/보너스/횟수권, 일시 정지, 다른 조직, member/anon 호출은 원장과 잔액을 바꾸지 않는다.
- 불변 환불 이벤트와 기존 회원권 이력에서 환불 금액·사유·담당자·시각을 조회한다.
- 경영 수당 미리보기는 환불 발생일의 음수 회원권 거래를 반영한다.
- 기존 전체 방문 취소와 미사용 회원권 전체 역분개는 그대로 동작한다.

## 구현자 선택

회원권 환급 가치 계산의 법적·계약상 기준은 제품이 추정하지 않는다. 이번 범위는 `할인 후 실판매액 = 발급 금액 잔액`인 단순 금액권에만 적용하며 외부에서 결정된 실제 환불액을 기록한다. 제한된 상품은 화면에서 사유를 설명하고 기존 정책 경로를 사용하도록 안내한다.
