# Business Assistant 상품화 UI/UX 설계서

- 작성일: 2026-09-17
- 상태: 구현 전 검토 대기
- 대상: PySide6 데스크톱 앱 전체 화면

## 1. 목표

현재의 기능 메뉴 셸을 실제 상품으로 사용할 수 있는 업무 애플리케이션으로 발전시킨다. 사용자는 로그인 후 조직과 현재 구독을 이해하고, 메뉴를 이동하며, 목록·검색·필터·편집·저장·오류 복구를 일관된 방식으로 수행할 수 있어야 한다.

핵심 원칙은 다음과 같다.

- 업무 데이터는 표와 폼을 중심으로 빠르게 조작한다.
- 권한이 없는 메뉴는 숨기기보다 이유와 필요한 구독을 설명한다.
- 네트워크 작업은 UI를 멈추지 않고 로딩·성공·실패 상태를 표시한다.
- 파괴적 작업은 확인과 되돌릴 수 있는 보관을 우선한다.
- 모든 화면은 조직 컨텍스트를 명확히 보여 주고, 서버 권한 검사를 전제로 한다.

## 2. 정보 구조와 화면 전환

### 앱 셸

- 상단 바: 제품명, 현재 조직 선택, 동기화 상태, 사용자 메뉴
- 좌측 내비게이션: 홈, 고객·거래처, 일정·할 일, 문서, 매출·지출, 파일·자료, 가져오기·내보내기, 보고서, 자동화, 알림, 팀, 연동, 계정·구독, 환경설정
- 중앙 콘텐츠: 현재 메뉴의 페이지
- 우측 선택 패널: 상세·편집 화면이 필요한 메뉴에서만 표시
- 전역 알림: 저장 성공, 네트워크 오류, 권한 부족을 토스트와 상태 배너로 표시

메뉴 클릭은 페이지를 교체하되, 목록 필터와 선택 상태는 세션 중 유지한다. 조직을 변경하면 이전 화면의 선택 상태와 캐시를 폐기하고 새 entitlement를 다시 조회한다.

### 첫 진입 흐름

1. 로그인
2. 조직이 없으면 조직 생성 온보딩
3. 조직이 있으면 현재 조직과 구독 요약 표시
4. 첫 사용자는 고객 등록, 일정 생성, 문서 작성 중 하나를 선택하는 시작 카드 표시

## 3. 디자인 시스템

- 기본 폰트: Windows 기본 한글 글꼴, 본문 14px, 제목 20~28px
- 색상 토큰: 배경 `#F7F8FA`, 표면 `#FFFFFF`, 본문 `#1F2937`, 보조 `#6B7280`, 강조 `#2563EB`, 성공 `#16A34A`, 경고 `#D97706`, 오류 `#DC2626`
- 모서리 8px, 간격 4px 단위, 최소 클릭 영역 36px
- 버튼 계층: primary(주요 저장/생성), secondary(보조), ghost(탐색), danger(삭제/보관)
- 표 행 높이 44px, 고정 헤더, 빈 상태와 페이지네이션을 표 컴포넌트에 포함
- 입력 오류는 필드 아래에 즉시 표시하고 서버 오류는 전역 배너로 표시

Qt 스타일시트는 색상·간격·타이포그래피를 토큰으로 관리하고 개별 화면에서 임의 색상을 쓰지 않는다.

## 4. 공통 화면 패턴

각 업무 화면은 다음 구조를 공유한다.

1. 페이지 제목과 한 줄 설명
2. 주요 작업 버튼(생성/업로드)
3. 검색·필터 바
4. 결과 표 또는 카드
5. 상세·편집 폼(우측 패널 또는 모달)

모든 API 호출은 `idle → loading → success/empty/error` 상태를 갖는다. 빈 상태에는 다음 행동을 직접 연결하고, 오류에는 재시도와 지원 정보(요청 ID가 있는 경우)를 제공한다.

## 5. 메뉴별 MVP UX

| 메뉴 | 핵심 화면 | 주요 상호작용 |
| --- | --- | --- |
| 홈 대시보드 | 오늘의 작업, 최근 고객, 재무 요약 | 카드 클릭으로 원본 화면 이동 |
| 고객·거래처 | 고객 표 + 상세 패널 | 검색, 생성, 편집, 보관 |
| 일정·할 일 | 상태별 칸반/목록 | 상태 변경, 마감일, 우선순위 |
| 문서 자동화 | 템플릿 목록 + 편집기 | 템플릿 생성, 문서 작성·보관 |
| 매출·지출 | 거래 표 + 기간 요약 | 수입/지출 필터, 합계, 등록 |
| 파일·자료 | 파일 표 + 업로드 영역 | signed 업로드, 다운로드, 보관 |
| 계정·구독 | 사용자·조직·요금제 | 현재 플랜과 기능 목록 확인 |

가져오기·내보내기, 보고서, 자동화, 알림, 팀, 연동은 공통 셸과 동일한 상태 패턴을 사용하며 API 구현 시 화면을 활성화한다.

## 6. 구독·권한 UX

- 메뉴 정의의 feature code를 서버 entitlement와 매칭한다.
- 비활성 메뉴에는 `(준비 중)` 대신 `플랜 업그레이드 필요` 또는 `관리자 권한 필요`를 표시한다.
- 기능 화면에 진입한 뒤에도 서버의 403을 처리해 권한 안내를 표시한다.
- 계정·구독 화면에서 현재 플랜, 만료일, 활성 기능을 한눈에 보여 준다.

## 7. 접근성·안정성 기준

- 모든 입력에 레이블과 키보드 포커스 순서를 제공한다.
- 색상만으로 상태를 구분하지 않고 아이콘·문구를 함께 사용한다.
- 창 크기 변경 시 표와 폼이 축소되며, 최소 창 크기를 보장한다.
- 저장 중 중복 클릭을 막고, 창 닫기 시 미저장 변경을 확인한다.
- API 타임아웃·오프라인·만료 토큰을 사용자 언어로 안내하고 로그인 화면으로 안전하게 복귀한다.

## 8. 구현 순서

1. 공통 `AppShell`, 디자인 토큰, 상태 배너·토스트·로딩·빈 상태 컴포넌트
2. 고객·거래처 화면(목록/검색/CRUD)으로 패턴 검증
3. 일정·할 일, 문서, 재무, 파일 화면 순서로 API 연결
4. 조직 선택·구독 요약·계정 화면 고도화
5. 가져오기·내보내기, 보고서, 자동화, 알림, 팀, 연동 화면 추가
6. Qt offscreen 테스트, 실제 Windows 화면 QA, 키보드 탐색·오류 상태 점검

각 단계는 공통 컴포넌트를 재사용하고, 기존 API 테스트와 함께 데스크톱 UI 테스트를 추가한다. 기능별 화면을 추가할 때마다 `scripts/check.ps1`을 통과시키고 한글 커밋으로 main에 push한다.

## 9. 검토 요청

이 설계는 현재 PySide6 데스크톱 앱, 조직·구독 entitlement, 구현된 서버 API를 기준으로 작성했다. 좌측 내비게이션 + 중앙 업무 화면 + 필요 시 우측 상세 패널 구조와 위 구현 순서를 승인하면 실제 UI 구현을 시작한다.
