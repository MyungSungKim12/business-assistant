# 후속 제품 기능 1~12 설계

사용자는 제시된 12개 항목 전체의 순차 구현과 필요한 SQL 작성·Supabase 직접 적용을 승인했다. 중간 완료 보고·추가 승인 질문 없이 진행한다. 제품 목표는 뷰티 매장 예약·고객·시술과 ERP 연결이며, 기존 React/Tauri 화면 구조와 사용자 미커밋 변경을 보존한다.

## 공통 결정 (구현자 선택)

- React 19/Tauri 2 + Node/Fastify + Supabase를 유지한다. 화면 리디자인은 제외하며 기능에 필요한 기존 스타일의 입력·설정·내역만 추가한다.
- API 조직·기능·역할 검증과 DB JWT·조직 경계를 모두 유지한다. 변경/삭제·타인 조직·멱등/충돌·실패 입력 보존을 검증한다.
- SQL은 기존 번호 다음부터 충돌 없이 순차 추가하고 격리 PostgreSQL 검증 후 원격 사전 점검→migration 적용→스키마/권한 검증을 진행한다. 기존 데이터 삭제·임의 업무값 채우기는 하지 않는다.
- 실제 고객에게 메시지를 발송하거나 임의 외부 계정을 생성하지 않는다. 새 기능의 발송은 실제 사용자가 요청한 동선에서만 수행한다. 공급자/도메인/서명키가 없으면 검증 가능한 구현·환경 계약·연결 안내까지 완성하고 운영 연결 미완료를 표시한다.
- 전체 테스트·실제 앱/휴대폰 운영 시험은 앞선 사용자 요청대로 마지막 인수 범위로 남긴다. 구현에 필요한 집중 검증·타입/빌드·격리 DB와 SQL 원격 적용 검증은 수행한다. 커밋·푸시·실제 서비스 공개 배포는 별도 요청 없이 하지 않는다.

## 항목과 수락 기준

1. **N1030-01 / CRM·DASH 성능:** 시술/매출은 서버 검색·선택 고객 ID 조회로 연결한다. 검색 결과 밖 선택은 유지하며 입력을 버리지 않는다. 홈의 고객 지표/최근·예정 목록은 서버에서 집계·제한 조회하고 관련 고객 이름은 필요한 ID만 조회한다. 정상 경로에서 전체 고객 배열을 받지 않는다.
2. **N1030-02 / SET-001 매장 예약 정책:** 매장 시간대/주간 영업일·시간, 날짜별 휴무·차단, 접수 마감·최소 사전 시간. 기본 정책은 비활성으로 기존 예약을 바꾸지 않는다. 생성/변경·반복·빈 시간 추천에 같은 검사를 적용하며 이미 확정된 기록은 자동 취소하지 않는다.
3. **N1030-03 / SET-003 계정:** 비밀번호 복구/확인 메일 재전송, 기기·세션 목록/선택 해제·전체 로그아웃. 계정 존재 여부를 노출하지 않는 응답, 허용된 복구 URL, 제한/재시도, 실제 로그인 세션 검증. 공급자 제한은 명시한다.
4. **N1030-04 / INT-007 전화 수신함:** 실시간 릴레이를 영속 이벤트/미응대·응대 완료·담당자·콜백 할 일에 연결한다. 동일 이벤트 중복 생성 금지, 기기/조직/사용자 동의·권한, 서버 재시작/다중 서버에서도 복구. 원문 수신 번호의 범위/보유와 표시 마스킹을 구분한다.
5. **N1030-05 / INT-006 번호부 증분:** 조직별 버전/변경 cursor·삭제 tombstone과 Android 원자 교체/증분 병합. 초기 전체 동기화와 오래된 cursor 재초기화, 동의 철회/로그아웃/조직 전환 경쟁 보호. 알 수 없는 수신 번호를 서버에 업로드해 조회하지 않는다.
6. **N1030-06 / MED-002 사진 정리:** 목록 조회와 무관한 제한된 주기 처리, 복구/실패 원인 및 재등록 안내. 실제 Storage 객체의 무조건 삭제는 하지 않는다. 보유기간과 물리 삭제는 기존 보안 정책에 따른다.
7. **N1030-07 / SET-002 업무 권한:** 역할 기본권한을 보존하고 고객 조회·시술·수납·환불 승인·내보내기 등의 업무 권한을 API/화면에 적용한다. 소유자 잠금 방지·관리자 변경 감사·권한 변경 후 캐시 무효화.
8. **N1030-08 / MKT 고객 발송:** 예약 확인/변경·전날·시술 후 안내의 템플릿·예약 발송·동의 검사·취소/중복 방지·실패 재시도·발송 이력. 공급자 어댑터 및 안전한 미설정 상태. 공급자 계정 없이 가짜 발송 성공을 표시하지 않는다.
9. **N1030-09 / APT 복수 시술:** 단일 방문 내 시술 순서/소요시간·담당자·자원 구간과 원자 충돌 검사, 일괄 수정/취소·기존 단일 예약 호환. 기존 반복 예약 시리즈와 구분한다.
10. **N1030-10 / INV 입력 편의:** 바코드 조회를 입출고·실사 입력에 연결하고 수량/로트/FEFO·원장 감사/동시 변경을 보존한다. 안전재고 부족 기반 발주 초안을 만들되 승인 없이 실제 발주/재고를 변경하지 않는다.
11. **N1030-11 / DOC 고객 서명:** 고객용 모바일 확인/서명 링크의 해시 저장·만료·일회 사용·철회·문서 버전 고정·증빙을 구현한다. 최소 데이터 공개, 링크 원문/서명 토큰 로그 금지. 실제 고정 HTTPS 주소가 없으면 배포 연결은 별도다.
12. **N1030-12 / OPS 배포 준비:** 고정 API 주소/허용 origin 계약·기기 등록/해제·서명/업데이트 검증과 진단·DB+Storage 복구 실행 절차를 완성한다. 자리표시자 키/주소로 운영 준비 완료를 표시하지 않는다. 실제 서버/도메인·키 연결과 공개 배포는 외부 선행 조건이다.

## 검증 범위

각 항목은 집중 실패 재현→최소 구현→회귀·타입→독립 검토→필요한 SQL 적용을 완료하고 다음 항목으로 진행한다. 로컬 코드 검증, 원격 스키마/권한 검증, 실제 사용자 동선/공급자/설치본 인수를 별도 기록한다.
