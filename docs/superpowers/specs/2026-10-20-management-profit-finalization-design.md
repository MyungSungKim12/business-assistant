# LAB-10 경영 손익 확정 스냅샷 설계

## 목적

경영 화면은 현재 등록된 매출·비용, 재고 원가, 확정 수당을 계산하지만 미확정 수당이나 미확인 원가가 있으면 잔액을 보류한다. 이 설계는 관리자가 해당 기간의 원장 입력이 완전하다고 확인한 뒤, 기록 데이터에 근거한 경영 손익 스냅샷을 확정하고 다시 조회할 수 있게 한다.

## 목표

- `inventory_cost_unknown_units = 0`이고 조회 기간 전일의 수당 확정이 완료된 때만 확정한다.
- owner/admin만 확정할 수 있으며 API와 DB RPC 모두 조직 역할을 검사한다.
- 확정 시점의 계산값, 기간, 조직, 담당자, 생성 시각, 확정 사유를 불변 스냅샷으로 저장한다.
- 동일 operation ID 재시도는 같은 결과를 반환한다. 같은 기간의 새 확정은 새 revision으로 기록하고 이전 스냅샷은 남긴다.
- 감사 로그에 `management.profit_finalize`를 기록한다.
- 화면은 확정 전 체크를 요구하고 확정된 값과 이전 revision 이력을 보여 준다.

## 경계와 제한

- 확정은 원장을 잠그지 않는다. 이후 원장 수정은 과거 스냅샷을 바꾸지 않으며, 수정된 값으로 다시 확정하면 새 revision이 생성된다.
- 최종값은 `operating_profit_after_recorded_tax`이며, 상품·시술 원가와 확정 수당이 반영되고 이미 입력된 세금·급여·기타 지출은 원장 지출에 포함된다.
- 확정 전에 관리자는 해당 기간의 수입·지출, 급여·수당, 세금 및 재고 원가가 모두 입력되었음을 확인한다. 확정본은 기록 완전성에 대한 관리자 확인 결과다.
- 공식 회계 재무제표·세무 신고나 신고 세액 산출로 표시하지 않는다. 확인된 입력 밖의 의무를 시스템이 검증하지 않는다.
- 개인정보 파기 D-10과 무관하며 CRM 데이터는 읽거나 수정하지 않는다.

## 오류와 권한

- 누락 원가, 수당 정산 공백, 잘못된 기간, 체크 미동의는 확정을 거절한다.
- operation ID 재사용이 다른 기간 또는 다른 confirmation payload와 충돌하면 거절한다.
- 다른 조직 데이터는 RPC 입력 조직과 현재 사용자 membership에서 재확인한다.
- 저장된 확정 행과 감사 로그는 수정·삭제할 수 없다.

## 수용 기준

- SQL 089의 PGlite 검증에서 확정 preflight, 원가·수당 누락 거절, owner/admin 권한, 조직 경계, operation 재시도/충돌, revision 이력, 감사 로그, immutable 보존을 확인한다.
- API 계약 테스트에서 관리자 경로, 입력 검증, 조직 ID/기간 응답 일치를 확인한다.
- React 테스트에서 준비되지 않은 기간 비활성화, 확인 체크, 성공 결과, 중복 클릭·오류 재시도를 확인한다.
- 실제 Supabase 적용은 사용자 작업으로 남기고 운영 검증과 구분한다.
