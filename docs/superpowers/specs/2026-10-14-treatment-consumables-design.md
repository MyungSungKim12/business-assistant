# 시술 소모품·회원권 연동 설계

## 목적

시술 완료를 재고 원장과 연결해 서비스별 소모품을 빠짐없이 차감하고, 방문 결제에서 회원권 횟수 차감 기능을 실제 매출 화면에서 사용할 수 있게 한다. 재고는 시술 상태와 원자적으로 변경하고, 회원권은 기존 방문·수납 원장과 같은 원칙을 사용한다.

## 범위

- 예약 서비스별 소모품 기준(실물 상품과 1회 시술당 소모 수량)을 관리자 화면에서 관리한다.
- 시술 기록에 적용 서비스를 연결한다. 서비스가 연결되지 않았으면 임의의 서비스/재고를 추정해 차감하지 않는다.
- 연결된 시술이 완료될 때 서비스 기준 수량을 재고에서 원자적으로 차감하고 불변 재고 원장에 `treatment_use` 이동을 남긴다.
- 재고 부족, 다른 조직의 서비스·상품, 중복 완료, 버전 충돌은 전체 요청을 거부하며 재고와 시술 상태 모두 유지한다.
- 기존 `WalletUseDialog`의 금액권·횟수권 적용을 매출 화면에서 열 수 있게 한다. 횟수권은 선택된 활성 시술 판매 줄에 한 번만 적용하며 기존 `use_customer_wallet` 원장이 잔액을 갱신한다.
- 기존 회원권 차감은 수납 단계에 둔다. 시술 완료 시점에 별도로 차감해 이중 차감하지 않는다.

## 제외

- 시술 중단/정정 후 자동 재고 복구, 유통기한·로트 추적, 공급처·발주 관리.
- 서비스별 수량 자동 계산 센서 또는 임의의 재고 수량 추정.
- 실 Supabase 데이터에 마이그레이션을 실행하는 일.

## 안전 규칙

- 재고 이동은 원장 insert와 `catalog_products.stock_quantity` 갱신을 한 DB 트랜잭션으로 처리한다.
- 한 시술에서 동일 상품은 한 레시피 행으로 합친다. 상품 행은 UUID 정렬 순서로 잠가 교착을 줄인다.
- 이전에 생성된 시술에는 서비스 연결이 없으므로 과거 재고를 소급 차감하지 않는다.
- 완료된 시술의 서비스 연결과 소모품 레시피는 이후 완료 처리에만 영향을 준다. 기존 소비 원장을 수정·삭제하지 않는다.
- 재시도는 기존 시술 상태 전이의 `operation_id`와 버전 잠금으로 중복 차감을 막는다.

## 인수 기준

1. 관리자가 서비스에 조직 내 활성 실물 상품과 양수 소모량을 설정·수정·삭제할 수 있다.
2. 다른 조직 상품, 회원권 상품, 중복 상품, 0/음수/범위 초과 수량은 거부된다.
3. 시술에 서비스가 연결되어 있고 재고가 충분하면 완료와 소모품 재고 차감이 한 번만 반영된다.
4. 서비스 연결 없음 또는 소모품 기준이 비어 있으면 재고가 임의 변경되지 않는다.
5. 재고 부족·권한 거부·다른 조직 접근·오래된 버전은 시술 완료와 모든 재고 행을 롤백한다.
6. 매출 화면에서 회원권 사용 창을 열어 금액권/횟수권을 적용할 수 있으며, 조직·고객·활성 시술 줄·잔액·멱등성 검사가 기존 API에서 유지된다.
7. 실 Supabase 적용·실제 화면 흐름은 별도 운영 인수로 남기고 코드만으로 `verified` 처리하지 않는다.
