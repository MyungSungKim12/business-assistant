# CRM-014 고객 보유·영구 파기 설계

작성일: 2026-10-21  
상태: 제품 초안 승인, 구현 진행 중  
선행: CRM 고객/조직 권한, SEC-04 감사, CRM-15 사진 보관·파기 범위

## 목적

고객 관계 종료 뒤 데이터 묶음별 보유기간과 법적 보류를 확인하고, 권한 있는 관리자가 검토·확인한 경우에만 파기 절차를 시작한다. 고객 보관(화면에서 숨김)과 개인정보 파기, 법정 보존 기록은 서로 다른 상태로 취급한다.

## 승인된 제품 방향

- 보유기간은 조직별·데이터 분류별로 설정한다.
- 기간 계산의 기준은 고객 관계 종료 시각이다. 최근 방문일이나 마지막 예약일을 관계 종료로 추정하지 않는다.
- 고객 프로필, 민감 상담정보, 시술 사진, 동의 증빙, 거래 기록, 분쟁 기록, 감사 이벤트의 기간을 각각 설정한다.
- 거래·법정 보존 자료는 고객 프로필에서 분리해 필요한 최소 정보만 보존하는 것을 목표로 한다.
- 분쟁/법적 보류가 활성화된 고객은 파기 후보에서 제외한다.
- 최종 파기는 관리자 확인과 개인정보를 최소화한 감사 이력을 요구한다.
- 각 기간은 사업자/조직 관리자가 확인해 입력한다. 임의의 기본 기간은 없다. 필수 분류 중 하나라도 미설정이면 후보 판단과 파기를 막는다.

## 데이터·상태 계약

1. `customer_retention_policies`: 조직별 분류 기간(일), 버전, 수정자·시각. 허용 기간은 양의 정수이며 미설정은 `NULL`이다.
2. 고객의 관계 종료 시각은 명시적인 관리자 동작으로만 기록한다. 미래 시각은 허용하지 않는다. 방문일/예약일에서 자동 생성하지 않는다. 예약 중(`reserved`, `confirmed`, `checked_in`)인 예약 또는 양의 금액/횟수 회원권 잔액이 있으면 종료를 거부한다.
3. `customer_legal_holds`: 고객별 보류 생성/해제 이력. 열린 보류가 하나라도 있으면 파기 불가. 사유에는 고객의 민감정보를 넣지 않도록 제한한다.
4. `customer_retention_events`: 정책 변경, 관계 종료/재개, 보류/해제 같은 관리자 조작의 최소 불변 이벤트. 원문 고객 정보나 파일 경로는 기록하지 않는다.
5. 보유기간이 모두 설정되고 관계가 종료되고 보류가 없어도, 현재 거래·회원권·예약·발급 문서·동의·시술 사진·Storage 객체 참조의 분리 및 원본/백업 파기 작업이 구현되기 전까지 최종 파기는 차단한다.

## 권한과 안전성

- 모든 쓰기는 요청 조직의 `owner` 또는 `admin` 권한으로 DB에서 재검사한다.
- 조직 밖 고객/정책/보류 접근은 동일한 존재 오류로 거부한다.
- 직접 테이블 쓰기는 허용하지 않고 검증된 RPC만 실행할 수 있다.
- RPC는 `SECURITY DEFINER`, 빈 `search_path`, 스키마-qualified 참조를 사용하며 `PUBLIC`/`anon` 실행 권한을 회수한다.
- 정책 버전이 바뀐 뒤 오래된 화면에서 저장한 값은 낙관적 버전 비교로 거부한다.
- 보류 해제와 관계 재개는 사유를 요구하고 이력으로 남긴다.
- 사용자 확인, 백그라운드 삭제 작업, Storage 실패 재시도, 백업 보존 기간은 파기 실행 단계의 별도 설계 및 인수 대상이다.

## 명시적 제한

이 초안은 특정 매장의 법률 적용이나 기간 값을 판정하지 않는다. 현재 고객 연결 테이블과 Storage 객체를 자동으로 지우지 않는다. 구성·보류·관계 종료 상태를 저장하고 검토 자료를 제공하는 준비 단계와, 실제 데이터 분리·삭제를 수행하는 단계는 별도로 검증한다. `audit_events`는 불변 로그이므로 고객 파기와 함께 삭제하지 않는다.

## 인수 조건

- 미설정 기간은 빈 상태로 남고 기본 일수를 생성하지 않는다.
- 기간 누락, 열린 보류, 종료되지 않은 관계, 오래된 버전 저장, 다른 조직, member/anon 요청은 DB에서 거부된다.
- 관리자 정책 변경/보류/해제/관계 종료 이벤트가 최소 메타데이터로 남는다.
- 보유기간이 입력돼도 실제 파기는 관련 레코드와 Storage 파기/복구 불가 증거가 완성되기 전에는 실행되지 않는다.
- SQL은 격리 PostgreSQL에서 검증한다. Supabase 적용·실조직 정책값 확인·실데이터 파기는 이 범위에 포함하지 않는다.
