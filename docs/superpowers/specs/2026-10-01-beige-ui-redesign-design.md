# 베이지 톤 전체 UI 리모델링 설계

## 1. 목적

현재 데스크톱 앱의 정보 구조와 업무 기능은 유지하면서, Drop Point의 카드 중심 레이아웃과 명확한 정보 계층을 참고해 뷰티 매장 운영 제품에 맞는 따뜻한 베이지 UI로 재정리한다. 로고·캐릭터·브랜드 요소와 소스 코드는 직접 복제하지 않고 자체 디자인 토큰과 컴포넌트로 구현한다.

## 2. 확정된 사용자 의도

- Drop Point처럼 사이드바, 카드, 요약 지표, 큰 주요 행동 버튼이 분명한 화면을 선호한다.
- 전체 톤은 파란색 중심이 아니라 밝고 따뜻한 베이지 계열이어야 한다.
- 기존 고객·예약·시술·문서·ERP 기능과 입력 보호, 권한 계약은 유지한다.
- 상품화 수준의 선명한 폰트, 안정적인 간격, 상태 표시, 빈 화면과 오류 화면까지 일관되게 보여야 한다.

## 3. 시각 언어

### 색상 토큰

| 역할 | 값 | 사용처 |
| --- | --- | --- |
| 작업 배경 | `#F7F3ED` | 전체 본문 배경 |
| 사이드바 | `#E8DED2` | 고정 내비게이션 |
| 카드 | `#FFFDF9` | 목록·요약·상세 패널 |
| 카드 보조 | `#F2EAE1` | 그룹 헤더·입력 영역 |
| 기본 글자 | `#403A35` | 제목·본문 |
| 보조 글자 | `#8D8378` | 설명·메타 정보 |
| 주요 강조 | `#B98B68` | 선택 상태·주요 버튼 |
| 강조 진한색 | `#8E684F` | hover·pressed·아이콘 대비 |
| 성공 | `#7E9B78` | 완료·정상 |
| 경고 | `#C99562` | 확인 필요·대기 |
| 오류 | `#B9786D` | 실패·차단 |
| 테두리 | `#E4D9CD` | 카드·입력창·구분선 |

색상은 장식보다 역할을 우선한다. 실제 지표가 없는 화면에 가짜 숫자나 장식용 상태를 추가하지 않는다.

### 형태와 간격

- 카드 모서리 12~16px, 입력창 8~10px, 버튼 8~10px
- 본문 기본 간격 16px, 카드 내부 20~24px, 주요 섹션 간격 24~32px
- 그림자는 강하게 사용하지 않고 `rgba(92, 67, 45, 0.08)` 수준의 얕은 그림자만 허용
- 아이콘은 기존 기능 의미를 유지하며 단색 웜 브라운 계열로 통일
- 선택 상태는 외곽선보다 옅은 베이지 배경과 좌측 포인트로 표시

## 4. 공통 화면 구조

1. 좌측 고정 사이드바: 브랜드 영역, 메뉴 그룹, 현재 메뉴, 하단 사용자·설정
2. 상단 헤더: 화면 제목, 짧은 설명, 화면별 주요 행동 버튼
3. 본문: 요약 카드 → 검색·필터 → 목록·작업 패널 순서
4. 상세 정보: 필요할 때 우측 패널 또는 하단 편집 영역으로 표시
5. 오류·빈 상태: 데이터가 없다는 사실과 다음 행동을 함께 표시

사이드바와 본문 폭은 현재 반응형 기준을 유지한다. 1100px 창에서 핵심 정보가 잘리지 않고, 125%·150% 배율에서 글자와 버튼이 겹치지 않아야 한다.

## 5. 메뉴별 적용 방향

- 대시보드: 오늘 예약·대기·매출·재고 경고를 실제 데이터 기반 요약 카드로 배치
- 고객관리: 고객 카드 목록과 선택 고객 상세 패널을 유지하되, 선택 상태와 최근 활동을 따뜻한 카드 계층으로 강화
- 예약관리: 날짜·담당자·상태를 색상과 카드로 구분하고 충돌·취소 상태를 별도 배지로 표현
- 상담·시술: 고객 정보, 이력, 작성 영역을 세 카드로 나누고 진행 상태를 단계형으로 표시
- 결제·매출: 확정 전 초안과 확정 원장을 시각적으로 분리하며 금액 강조색은 베이지와 브라운으로 제한
- 문서·파일: 업로드·발행·다운로드 진행 상태와 재시도 행동을 카드 안에서 명확히 제공
- 설정·권한: 일반 사용자가 이해할 수 있는 용어와 설명형 폼을 사용

## 6. 구현 경계

이번 리모델링은 `workspace_style.py`, `design_tokens.py`, 공통 UI 컴포넌트와 각 메뉴의 표시 계층을 중심으로 진행한다. API 계약, Supabase 저장 구조, 권한 검사는 변경하지 않는다. 기능 추가가 필요한 경우 해당 제품 기능 ID를 별도로 만들고 UI 작업과 섞지 않는다.

## 7. 단계별 구현 순서

1. 공통 색상 토큰·사이드바·헤더·버튼·입력·카드 스타일
2. 대시보드와 고객관리의 대표 화면
3. 예약·상담·시술 화면
4. 문서·파일·결제·정산 화면
5. 빈 상태·오류·로딩·권한 없음·읽기 전용 상태
6. 폰트 선명도와 1100/1440px, 125/150% 배율 회귀 검증

## 8. 검증 기준

- 기존 데스크톱 테스트가 모두 통과한다.
- 공통 스타일 변경으로 기존 입력 보호, 메뉴 전환, 저장·취소 동선이 깨지지 않는다.
- 각 대표 메뉴를 실제 Qt 위젯으로 렌더링해 밝은 배경에서 글자 대비와 선택 상태를 확인한다.
- 실제 고객 데이터나 외부 서비스 호출 없이 화면 상태를 검증한다.
- 사용자 Windows 환경에서 확인하기 전에는 상품화 완료로 표시하지 않는다.

## 9. 남은 위험과 제한

- Windows ClearType·혼합 DPI에서의 최종 글자 선명도는 사용자 PC 확인이 필요하다.
- 실제 메뉴별 정보량이 늘어나면 1100px 화면에서 카드가 과밀해질 수 있으므로 대표 화면부터 단계적으로 적용한다.
- 참고 프로젝트의 AGPL-3.0 라이선스와 브랜드 리소스는 직접 재사용하지 않는다.
