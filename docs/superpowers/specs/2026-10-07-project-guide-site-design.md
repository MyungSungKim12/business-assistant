# Business Assistant 프로젝트 가이드 사이트 설계

## 목표

현재 저장소에 흩어진 제품 계획, 실행 안내, 화면 캡처와 기능별 적용 문서를 하나의 검색 가능한 한국어 문서 사이트로 묶는다. 사용자는 화면 기능을 따라 할 수 있고, 운영자는 Supabase와 권한을 관리할 수 있으며, 개발자는 저장소 구조와 Git worktree 흐름을 이해할 수 있어야 한다.

## 독자

- 매장 실무자: 고객, 시술, 문서, 장바구니, 수납 기능을 사용한다.
- 매장 관리자: 조직 권한, 파일, 재무, 데이터 적용 상태를 확인한다.
- 개발자: 로컬 실행, 마이그레이션, 테스트, 브랜치와 worktree를 관리한다.

## 정보 구조

1. 시작하기: 제품 개요, 빠른 시작, 로그인과 화면 구성
2. 화면 사용법: 현재 구현된 메뉴와 준비 중 메뉴를 명확히 분리
3. 업무 시나리오: 신규 고객부터 상담, 시술, 결제, 환불까지 연결
4. 운영자 가이드: Supabase, 권한, Storage, 백업과 운영 점검
5. 개발자 가이드: 저장소 구조, Git/worktree, 검증과 문서 갱신
6. 문제 해결: 실행, 연결, 권한, 사진과 수납 오류의 진단 순서
7. 제품 계획: 기존 `docs/product` 문서를 원본 그대로 연결

## 구현 방식

- MkDocs Material을 사용해 Markdown 원본, 검색, 반응형 탐색과 Mermaid를 제공한다.
- `docs/guide`에 독자용 문서를 두고 기존 `docs/product`는 기능 상태의 단일 출처로 유지한다.
- 기존 `docs/screenshots`의 검증된 화면 캡처를 재사용한다.
- GitHub Actions는 pull request에서 엄격 빌드를 검사하고 `main` 반영 시 GitHub Pages에 배포한다.
- 비밀키, 고객 데이터, 운영용 연결 문자열은 사이트에 포함하지 않는다.

## 품질 기준

- 실제 메뉴명과 버튼명을 코드에서 확인해 사용한다.
- 구현되지 않은 메뉴를 사용할 수 있는 것처럼 설명하지 않는다.
- 정상 흐름과 함께 권한, 취소, 재시도, 미확인 결과를 설명한다.
- 모든 내부 링크와 이미지가 엄격 빌드를 통과한다.
- 모바일과 데스크톱에서 탐색 구조가 무너지지 않는다.

## 배포 경계

이번 변경은 배포 가능한 구성을 추가하지만 GitHub Pages 게시 자체와 원격 저장소 push는 수행하지 않는다. 게시 시점은 저장소 소유자가 결정한다.
