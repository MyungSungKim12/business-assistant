# 감사 로그 조회·보관 기본 정책

## 목적

매장 owner/admin이 민감 작업 이력을 앱에서 검색·검토해 운영 문제를 추적할 수 있게 한다. API와 DB의 기존 권한·조직 경계를 재사용하며, 화면에서 수정하거나 삭제하지 않는다.

## 범위

- 기존 `GET /api/v1/organizations/{organizationId}/audit-events`를 호출하는 읽기 전용 메뉴 화면을 추가한다.
- 기간, action 코드, 페이지 이동을 지원한다. 시각, action, 대상, 행위자 ID, 출처, 요청 ID, IP, 제한된 metadata를 표시한다.
- owner/admin에게만 메뉴를 보이고, API의 기존 구성원 권한 검사를 계속 적용한다.
- 로드 실패/빈 결과/다음 페이지/다시 시도 경로를 검증한다.
- 감사 이벤트는 기존 append-only 규칙과 같이 자동 삭제하지 않고 무기한 보관한다. 보관 기간을 요구하는 법률·계약·고객 정책을 확인하기 전 파기 기능을 만들지 않는다. 이 기본 정책과 보관 비용 위험을 운영 문서에 기록한다.

## 제외

- 감사 행 수정·삭제·파기, export, 행위자 이메일/실명 역조회, 화면 재디자인.
- 새 DB 마이그레이션과 권한 정책 변경.

## 인수 기준

1. owner/admin만 메뉴를 볼 수 있고 직접 API 접근도 기존 API가 거부한다.
2. 페이지네이션은 API cursor를 그대로 사용하고 organization 변경 시 이전 결과를 지운다.
3. 날짜/action 필터 변경 시 첫 페이지부터 다시 요청하며 잘못된 입력을 서버가 거부한다.
4. 실패 후 재시도 가능하고 입력 필터는 유지된다.
5. 감사 로그의 저장/삭제 정책이 문서에 명시되고 앱에 파기 동작이 노출되지 않는다.
