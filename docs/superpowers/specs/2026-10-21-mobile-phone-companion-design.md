# Android·iOS 전화 고객 연결 설계

작성일: 2026-10-21 · 상태: 사용자 요청에 따라 구현 진행 · 기능 ID: INT-005, INT-006

## 목적

개인 휴대전화로 전화가 왔을 때 고객을 빠르게 식별하고 전화 상담 메모를 고객 이력에 남긴다. 기존 React/Tauri와 Node API를 유지하면서 모바일 운영체제의 전화 식별 기능을 사용한다.

## 현재 기준

- 현재 앱은 React 19 + Tauri 2 데스크톱 앱이며 모바일 타깃/전화 기능은 초기화되어 있지 않다.
- 고객 연락처는 조직 범위 `customers`에 저장되어 있고 고객 활동 API가 `customer_activities`에 이력을 기록한다.
- API는 `crm.basic` 조직 권한을 확인한다. 구독 `plan_features` 기반 메뉴/기능 권한 기초가 있다.
- 고객 검색은 현재 번호 검색을 지원하지만 휴대전화 네이티브 플러그인이 쓸 최소 정보 전화번호부 API는 없다.
- Windows 빌드 환경에는 Android SDK/Java 및 Apple Xcode가 확인되지 않았다. iOS 타깃 생성·서명·실기기 검증은 macOS/Xcode가 필요하다.

## 범위

1. 조직 로그인 사용자가 동의한 경우에만 이름, 전화번호, 고객 ID, 고객 상태의 최소 전화번호부 스냅샷을 기기에 동기화한다. 메모, 이메일, 생년월일, 사진 등은 내려보내지 않는다.
2. 전화번호 검색은 국가번호와 구분 기호를 정규화해 정확히 일치하는 고객을 반환한다. 미등록·중복 번호는 모호한 상태로 표시하고 임의로 연결하지 않는다.
3. Android `CallScreeningService`는 사용자가 기본 통화 선별 역할을 허용한 경우 수신 번호를 로컬 스냅샷에서 찾는다. 전화는 항상 즉시 허용 응답하고 식별/메모 실패가 통화 연결을 지연하거나 차단하지 않는다. 식별 결과는 전화 화면의 발신자 표시와 사용자 선택 알림으로 전달한다.
4. iOS Call Directory 확장은 동기화된 번호와 이름으로 iPhone 기본 전화 화면에 발신자 식별을 표시한다. 일반 이동통신 통화 이벤트를 앱이 받아 자동 로그를 남기는 기능은 포함하지 않는다. 사용자가 동반 앱에서 번호를 확인하고 메모를 저장한다.
5. 메모는 기존 고객 활동 API에 `activity_type=phone_call`로 저장한다. 전용 통화 녹음이나 통화 제어는 포함하지 않는다.
6. 사용자는 전화번호부 동기화를 끄고, 로그아웃·조직 전환 시 로컬 전화번호부를 지울 수 있어야 한다. 앱 잠금화면 알림은 기본적으로 고객명을 숨긴다.

## 의도적으로 제외하는 것

- iOS에서 일반 SIM 통화의 자동 통화 이벤트 수집, 통화 직후 강제 팝업, 통화 제어
- Apple Live Caller ID Lookup의 PIR 서버, Apple 릴레이 엔드포인트 검증 및 운영 등록
- 통화 녹음/녹취, LG U+ Centrex 연동, SMS·알림톡·이메일 발송
- 조직 고객정보를 사용자 동의 없이 개인 기기에 복제하는 동작

Apple의 실시간 발신자 조회는 별도 PIR/릴레이 인프라와 Apple 엔드포인트 검증이 필요하다. 전화번호를 서버에 알리지 않는 구조라 앱 서버의 자동 통화 로그 근거로도 쓸 수 없다. Android는 전화 선별 역할과 5초 이내 응답 요구가 있으므로 동기식 서버 호출을 하지 않는다.

## 권한·개인정보 경계

- 전화번호부 API, 번호 조회, 메모 저장은 모두 로그인 access token과 `crm.basic` 조직 접근 검사를 거친다.
- API는 요청 조직과 고객의 `organization_id`를 대조한다. 조직 간 고객 ID 조회를 거부한다.
- 네이티브 콜백은 통화 응답에 필요한 번호만 로컬에서 읽는다. 외부 전송은 사용자가 연결된 조직으로 로그인하고 기능을 켠 경우로 제한한다.
- 동기화 데이터는 전화 식별에 필요한 최소 정보로 제한한다. 앱 로그와 OS 알림에 전화번호/메모를 기록하지 않는다.
- 현재 Windows 작업공간에서는 웹/API 계약과 React 흐름을 테스트한다. Android·iOS 네이티브 패키지 및 기기 인수는 각 플랫폼 빌드 환경에서 별도로 기록한다.

## 인수 조건

- 정확한 번호만 매치되며 하이픈/공백/국가번호 표기 차이는 정규화 후 처리된다.
- 같은 번호에 고객이 둘 이상이면 `ambiguous`를 반환하고 메모 저장을 위해 사용자가 고객을 선택한다.
- 다른 조직 ID, 로그인 없는 요청, CRM 권한 없는 사용자는 조회·저장이 거부된다.
- 동기화 응답에는 이름·전화번호·고객 ID·상태 외 고객 필드가 없다.
- Android 네이티브 구현은 5초 제한과 무관하게 허용 응답을 먼저 반환하며 번호 숨김·네트워크 오류에도 통화를 차단하지 않는다.
- iOS는 시스템 발신자 식별과 앱 내 수동 상담 메모의 범위를 표시하고 Android와 동일한 자동 수신 이력이 있다고 표시하지 않는다.
- 동기화 해제/로그아웃/조직 전환에서 기기 전화번호부를 지우는 동작을 검증한다.

## 외부 검증 제한

Windows에는 Android SDK/Java가 없어 Android 번들 빌드를 수행하지 못했다. Xcode와 iOS 기기가 없어 Call Directory Extension 생성·서명·실기기 검증도 불가능하다. 이 제한을 감춘 채 플랫폼 기능을 `verified`로 표시하지 않는다.
