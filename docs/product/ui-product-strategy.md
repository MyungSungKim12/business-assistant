# 상품형 데스크톱 UI 전략

기준일: 2026-10-08 · 대상: Business Assistant 데스크톱 앱 · 상태: in-progress

이 문서는 Codex·Claude처럼 오래 사용해도 피로하지 않고, 처음 봐도 제품처럼 느껴지는 업무 앱을 만들기 위한 공통 전략이다. 특정 앱의 화면을 복제하지 않고, 그들이 공통으로 사용하는 정보 구조·밀도·상태 표현을 우리 제품의 고객·예약·시술·매출 흐름에 맞게 적용한다.

## 1. 상품성의 기준

상품성은 장식의 양이 아니라 다음 네 가지가 동시에 맞는 상태로 정의한다.

- **신뢰감:** 저장·동기화·권한·오류 상태가 명확하다.
- **집중:** 한 화면에서 사용자가 해야 할 다음 행동이 하나로 보인다.
- **속도감:** 화면 이동보다 목록 탐색과 상세 확인이 빠르다.
- **일관성:** 메뉴를 바꿔도 같은 위치·같은 표현·같은 단축 흐름을 사용한다.

## 2. 공통 앱 셸

모든 화면은 `앱 셸 → 작업 영역 → 상세 패널`의 세 층을 가진다.

```text
┌ 앱 셸 ─────────┬ 작업 영역 ───────────────────────────────┐
│ 매장 전환       │ 제목 · 검색 · 주요 행동                    │
│ 매장 운영       │ 목록/보드/캘린더                           │
│ 자료·분석       │                                            │
│ 설정·도움말     │ 선택한 항목의 상세 패널                    │
└────────────────┴────────────────────────────────────────────┘
```

앱 셸은 216px 내외의 고정 영역으로 두고, 메뉴는 그룹 제목과 하위 항목을 사용한다. 선택 상태는 전체 테두리가 아니라 옅은 배경과 좌측 2px 표시선으로 표현한다. 부가 메뉴는 항상 화면에 펼쳐 두지 않고 메뉴 버튼이나 더보기 메뉴로 감춘다.

## 3. 타이포그래피

현재 앱의 업무 UI 기준은 UI 글꼴 14px이다. 작은 글자를 무리하게 줄이지 않는다.

| 역할 | 크기 | 굵기 | 용도 |
| --- | ---: | ---: | --- |
| 화면 제목 | 22px | 600 | 페이지 제목 |
| 섹션 제목 | 15px | 600 | 카드·패널 제목 |
| 본문·메뉴 | 14px | 400~500 | 실제 업무 정보 |
| 보조 정보 | 12~13px | 400 | 날짜·상태·힌트 |
| 숫자·강조 | 14~16px | 600 | 금액·건수·상태 |

서체의 인상은 크기보다 획, 줄 간격, 굵기 단계, 색상 대비를 함께 조정한다. 한 화면에서 사용할 굵기는 Regular·Medium·SemiBold 세 단계로 제한한다.

## 4. 고객관리 기준 화면

고객관리 화면을 전체 제품의 기준 화면으로 삼는다.

- 왼쪽은 검색·필터·고객 목록이다.
- 중앙 또는 우측은 선택 고객의 상세 패널이다.
- 상세 패널은 `개요 / 상담 이력 / 시술 / 사진 / 결제` 탭을 사용한다.
- 저장·보관·새 고객 같은 주요 행동은 화면당 1개의 강조 버튼만 둔다.
- 고객 카드에는 이름·최근 방문·상태만 보여 주고, 태그·메모·사진은 상세에서 확인한다.
- 선택 고객을 바꾸어도 작성 중인 입력은 보호하고, 로딩은 상세 패널 안에서만 표시한다.

## 5. 공통 컴포넌트 규칙

- 버튼 높이와 입력창 높이는 전 메뉴에서 동일하게 유지한다.
- 검색창은 검색 아이콘, 지우기, 결과 건수를 한 묶음으로 둔다.
- 빈 상태는 설명과 다음 행동을 함께 제공한다.
- 오류는 원인·재시도·현재 입력 보존 여부를 한 줄 안에서 알려 준다.
- 로딩은 화면 전체를 막지 않고 해당 목록이나 패널 내부에서만 표시한다.
- 더보기 메뉴에는 삭제·보관·내보내기처럼 빈도가 낮은 행동을 둔다.

## 6. 구현 순서

1. 공통 앱 셸과 메뉴 상태를 정리한다.
2. 고객관리 화면을 기준 화면으로 완성한다.
3. 예약·시술관리를 고객 상세 패널 규칙에 맞춘다.
4. 결제·매출·재고 화면의 표와 상태 카드를 같은 컴포넌트로 통일한다.
5. 로딩·빈 상태·오류·권한 없음 화면을 전 메뉴에 적용한다.
6. 100%·125%·150% 배율과 실제 Windows 모니터에서 인수한다.

## 7. 완료 조건

화면 하나의 예쁜 스크린샷이 아니라, 메뉴를 이동하고 고객을 선택하고 저장·취소·재시도하는 전체 흐름이 같은 규칙으로 보일 때 완료로 본다. UI-001은 실제 Windows 모니터 인수 전까지 `in-progress`로 유지한다.
