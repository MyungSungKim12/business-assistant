# 기능 우선순위 1~6 현재 인수 점검

기준: 2026-10-12. **코드의 로컬 검증과 실제 Supabase/Windows 인수는 별개**다. 사용자는 031~036 SQL 실행을 보고했다. 현재 작업 환경에는 서비스 키가 없어 이를 독립 확인하지 않았고 운영 데이터는 변경하지 않았다.

## 새 SQL 적용 순서

사용자 보고 기준으로 036까지 적용됐다. 현재 코드의 다음 신규 기능을 실제 앱에서 확인하려면 `migrations/037_appointment_availability.sql`을 적용하고 서버와 데스크톱을 같은 소스 버전으로 재시작한다. 이 문서는 SQL 실행 승인을 요청하는 문서가 아니라 검증 가능한 적용 순서다.

`scripts/verify-live-schema.py`는 서비스 키가 설정된 환경에서 031~035와 037의 공개 테이블/컬럼 노출을 읽기 전용으로 확인한다. 서비스 키가 없으면 검증하지 못했다고 종료하며, 테이블 내용을 출력하지 않는다. 036의 권한 검사는 별도의 관리자·직원 실계정으로 확인한다.

2026-10-12 최신 소스를 임시 포트로 실행해 개발 계정 로그인·조직 조회와 034의 예약/담당자/서비스 읽기 API가 실제 Supabase에서 HTTP 200인 것을 확인했다. 운영 수지와 고객 회원권 조회는 해당 계정의 기능/관리 권한 때문에 HTTP 403으로 거부되어 035·036을 독립 검증하지 못했다. 임시 서버는 검증 후 종료했으며 기존 8000 포트 프로세스는 유지했다.

## 실제 화면 인수 순서

1. 관리자 계정으로 예약 담당자와 서비스를 만들고 고객 예약을 등록한다. 같은 직원의 60분 서비스+10분 여유 뒤 60분 지점 예약은 거절되고 70분 지점은 허용돼야 한다. 확정 → 방문 처리 후 매출·지출의 방문 장바구니를 확인한다.
2. 예약 변경 중 네트워크를 끊었다 재연결했을 때 입력을 잃지 않는지 확인한다. 같은 요청 재전송은 한 예약만 남아야 한다. 다른 조직/직원 계정에서는 관리자 마스터/관리 보고서가 보여서는 안 된다.
3. 회원권을 정지하고 사용을 시도해 거절되는지 확인한다. 재개 후 사용 및 기간 연장과 변경 사유를 확인한다. 응답이 불명확하면 같은 요청 재확인을 이용한다.
4. 홈의 오늘 예약과 현재 미수 금액이 원본 예약/미수 목록과 일치하는지 확인한다. 한 원천을 실패시켜 다른 카드 값이 남고 실패 카드에 재시도가 나타나는지 확인한다.
5. 관리자 운영 수지 창에서 기록된 거래 합계와 담당 판매 근거가 맞는지 확인한다. 수당/최종 손익으로 표시되지 않아야 한다.

기능 상태는 각 `docs/product/menus` 문서의 ID별 `in-progress`/`planned`를 따른다. 이 문서의 로컬 테스트 통과만으로 P0 전체를 `verified`로 올리지 않는다.
