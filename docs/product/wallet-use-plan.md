# 회원권 사용·차감 계획 — 2026-10-07

기능: WAL-002 · 선행: 027 상품/회원권 판매 및 지갑 발급 · 상태: `in-progress`

## 1차 범위

- 고객 방문의 활성 시술 항목에 고객 본인의 유효한 회원권을 적용한다.
- 금액권은 입력한 원 단위 금액을 잔액과 방문 미수금에서 함께 차감한다.
- 횟수권은 한 번에 1회를 차감하고 선택한 시술 항목의 아직 적용되지 않은 금액을 방문 결제에 반영한다.
- 복합 회원권은 한 요청에서 금액 또는 횟수 중 한 방식만 사용한다. 사용자가 어떤 혜택을 썼는지 원장에 명확히 남긴다.
- 현금·카드·이체 수납액과 회원권 적용액을 합산해 장바구니를 `collecting` 또는 `paid`로 전환한다. 회원권 사용은 이미 판매된 혜택의 소비이므로 새 재무 수입을 만들지 않는다.

## 데이터·동시성 계약

- `wallet_usage_ledger`: 조직, 지갑, 방문, 장바구니, 시술 판매 행, 사용 방식, 잔액 변화, 방문 적용 금액, 작업 ID, 담당자, 시각을 보관하는 불변 원장.
- 지갑 행과 장바구니 행을 잠근 뒤 잔액·유효기간·고객·상태·미수금을 다시 검사한다.
- 동일 작업 ID 재전송은 같은 결과를 반환하고, 다른 내용으로 재사용하면 거부한다.
- 잔여 1회에 서로 다른 요청이 동시에 들어오면 지갑 잠금 뒤 하나만 성공한다. 잔액은 음수가 될 수 없다.
- 횟수권은 같은 시술 판매 행에 이미 횟수 사용이 있으면 다시 사용할 수 없다. 금액권은 남은 시술 금액 범위에서 여러 지갑/요청을 적용할 수 있다.

## 고정 인터페이스

- RPC `use_customer_wallet(p_organization_id,p_visit_id,p_wallet_id,p_sale_line_id,p_mode,p_amount,p_expected_cart_version,p_operation_id,p_confirmed)` → 방문 수납 스냅샷.
- RPC `list_customer_wallets` 응답은 기존 잔액 정보에 `usage_history`를 추가한다.
- API `POST /organizations/{organization_id}/visits/{visit_id}/wallet-usages`.
- 요청: `wallet_id`, `sale_line_id`, `mode`(`money`/`count`), `amount`(금액 방식만 원 정수 문자열), `expected_cart_version`, `operation_id`, `confirmed=true`.

## 화면·실패 처리

- 방문을 선택한 결제 장바구니에서 고객 회원권 창을 연다. 시술 항목, 회원권, 사용 방식을 선택하고 예상 차감과 적용액을 확인한 뒤 사용한다.
- 처리 중 중복 입력을 막고, 결과가 불명확하면 서버+사용자+조직+방문별 복구 정보로 같은 작업 ID를 다시 확인한다.
- 명확한 입력/권한/충돌 오류는 재조회 후 다시 선택하게 하고, 네트워크 오류나 재시도 후 로그인 오류는 작업 ID를 보존한다.
- member는 조회만 가능하며 owner/admin만 차감할 수 있다. 다른 조직·고객·방문 데이터는 DB와 API에서 모두 거부한다.
