# 장바구니 할인 적용 안내

작성일: 2026-10-08 · 기능: SALE-004 · 상태: 로컬 코드·격리 검증 완료, 실환경 인수 대기

## SQL 적용 순서

사용자는 030을 적용 완료했다고 보고했다. 아직 적용하지 않았다면 SQL Editor에서 다음 두 파일을 이 순서로 각각 한 번 실행한다.

1. `migrations/031_customer_product_returns.sql`
2. `migrations/032_sale_cart_discounts.sql`

031이 이미 적용되어 있다면 032만 실행한다. 운영 DB에 접속해 적용 여부를 확인하거나 SQL을 실행하지 않았다.

## 사용 흐름

방문별 결제 장바구니의 **금액 검토** 영역에서 금액 할인 또는 비율 할인을 선택하고 값을 입력한다. 사유와 확인 항목을 채워 저장하면 서버가 할인액과 최종 금액을 계산한다. 결제 시작 전에 다시 수정하거나 해제할 수 있고, 최근 변경 이력은 할인 문구에 마우스를 올려 확인한다.

- 금액 할인은 원 단위 정수이며 소계보다 작아야 한다.
- 비율 할인은 1~99%이며 할인 후 결제 금액이 남아야 한다.
- 장바구니 품목을 바꾸면 비율은 새 소계 기준으로 다시 계산한다. 기존 정액 할인이 새 소계 이상이 되면 품목 변경을 거부한다. 할인을 먼저 수정/해제해야 한다.
- 첫 현금·카드·이체 수납 또는 회원권 사용이 시작되면 할인 변경은 잠긴다. 할인 변경 시 장바구니는 다시 검토 완료해야 수납할 수 있다.
- 상품 일부 반품 환불 상한은 장바구니 할인액을 품목별 금액에 비례 배분하고, 반올림 잔액은 마지막 품목에 반영해 계산한다.

## 현재 범위

owner/admin 수동 할인 한 가지를 지원한다. 쿠폰, 적립 포인트, 할인 조합 순서, 세금·직원 수당·원가 배분, 외부 프로모션 연동은 추가 업무다. 100% 무료 판매는 현재 수납 완료 흐름이 없어 지원하지 않는다. 실 결제 승인이나 외부 결제 할인은 실행하지 않는다.

- 격리 PGlite 12개 환불/할인 시나리오 통과: 금액·비율 할인, 서버 합계, 장바구니 변경 재계산, 과도한 할인 거부, 삭제, 결제 후 잠금, 재시도·충돌·역할 경계, 할인 상품 반품 한도와 전체 취소 재고 복원.
- 서버 장바구니 API/repository 23개, 데스크톱 장바구니/수납/API 관련 31개 통과.
- 전체 Supabase 적용, 다중 세션 동시성, 실제 결제, Windows 사용자 인수는 미실행이다.
