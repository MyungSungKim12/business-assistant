# 환불·취소 반대 원장 적용 안내

작성일: 2026-10-07 · 기능: SALE-003, WAL-003, INV-002 · 담당: Codex  
상태: 1차 환불 기록 로컬 구현·검증 완료, 실환경 인수 전 `in-progress`

## 사용할 수 있는 흐름

방문 수납 창의 **환불 · 사용 취소**에서 원영수증을 선택하고 금액과 사유를 입력한다.

- 현금·카드·이체는 원영수증의 남은 환불 가능액 안에서 부분 또는 전체 환불을 기록한다.
- 회원권 사용은 해당 사용 건 전체만 취소하며 차감한 금액 또는 1회를 복원한다.
- 환불이 기록되면 해당 방문 판매는 종료되어 새 수납이 섞이지 않는다. 남은 금액을 다시 청구하려면 새 방문/판매 건을 만든다.
- 누적 순수납액이 0원이 되면 판매 상품 재고를 복원하고, 그 판매로 발급된 미사용 회원권을 회수한다.
- 발급 회원권이 이미 사용되어 잔액이 달라졌으면 전체 취소를 모두 롤백하고 거부한다.

이 화면은 카드사·은행·PG 취소를 실행하지 않는다. 외부 취소를 확인한 뒤 내부 환불 및 반대 원장을 기록하는 기능이다.

## SQL 적용 순서

024~026 적용 완료를 사용자가 보고했다. 027~029, 031의 운영 DB 적용은 수행/확인하지 않았다. 030은 사용자가 적용 완료했다고 보고했다.

1. 027 → 028 → 029 → 030 순서로 적용한다. 사용자는 030 완료를 보고했다.
2. 다음 새 파일인 `migrations/031_customer_product_returns.sql`을 한 번 실행한다.
3. 같은 소스 버전의 서버와 데스크톱을 재시작한다.
4. [고객 상품 반품 적용 안내](customer-product-returns-release.md)의 테스트 조직 시나리오를 확인한다.

## 보호 규칙

- owner/admin만 환불을 기록하고 member는 내역만 조회한다.
- 환불은 원영수증 또는 회원권 사용 ID를 반드시 참조한다.
- 누적 환불액은 원수납액을 초과할 수 없고 회원권 사용 취소는 한 번만 가능하다.
- 원영수증·환불·재무 지출·회원권 복원·재고/발급 반대 원장은 수정·삭제할 수 없다.
- 작업 ID 재전송은 같은 결과만 반환한다. 통신 결과가 불명확하면 앱 재실행 후 같은 요청으로 확인한다.
- 전체 취소 중 한 항목이라도 복원할 수 없으면 환불 재무행을 포함한 전체 요청을 롤백한다.

- 서버/common **434 passed**. 입력 계약, 관리 권한, 원천 ID 전달, 환불 포함 수납 합계 검증을 확인했다.
- Qt 데스크톱 **229 passed**. 원영수증 선택, 금액·사유·명시 확인, 회원권 전체 취소 제한과 환불 결과 표시를 확인했다.
