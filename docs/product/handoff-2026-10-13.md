## 1. 프로젝트 한 줄 요약

뷰티 매장 운영 앱(고객·예약·시술·매출·재고·문서·직원·재무). 원래 Python(FastAPI + PySide6)이었으나 **Node API(Fastify) + React 19 + Tauri 2**로 전환을 끝냈고 Python 코드는 모두 제거되었습니다. UI·앱 셸(트레이 등)은 LCID 프로젝트의 구조를 이식했습니다.

## 3. 작업 규칙

- **브랜치는 `main` 하나만** 사용합니다. 기능 브랜치·worktree를 만들지 않습니다. 푸시하면 GitHub Actions(`ci.yml`: web/rust/audit, `docs-pages.yml`: mkdocs strict 빌드와 Pages 배포)가 돕니다. 푸시 후 통과 여부를 확인하고 실패하면 다음 커밋으로 고칩니다.
- 커밋 메시지는 `기능:` `수정:` `문서:` `운영:` 같은 종류로 시작하는 한국어. 사용자가 요청할 때만 커밋·푸시합니다.
- **비밀값은 저장소에 두지 않습니다.** `.env`(서비스 키, DB URL, 개발 자동 로그인 값)는 커밋 금지. `run-app.ps1`은 서비스 키 등을 앱 프로세스로 넘기지 않습니다. 비밀번호·키를 채팅에 적거나 화면에 입력하지 않습니다.
- 모든 API는 조직·기능·역할을 서버에서 검사합니다(화면 차단만으로 권한을 보장하지 않음).
- 문서를 바꾸면 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/docs/validate-guide.ps1`로 확인합니다(mkdocs strict).
- Windows에서 한글 콘솔 출력이 깨지는 것은 표시 문제일 뿐 파일은 UTF-8입니다. 복잡한 한글·백틱 heredoc은 셸이 깨뜨리므로 파일 쓰기 도구나 node 스크립트로 수정합니다.

## 4. 자주 쓰는 명령

```powershell
corepack pnpm install
.\run-app.cmd                                   # 개발용: API 서버 + vite + Tauri 앱 (운영에서는 쓰지 않음)
.\scripts\run-admin.ps1                         # 관리자 API(8001). 앱의 '구독' 메뉴가 보이려면 필요
corepack pnpm --filter @business-assistant/api test
corepack pnpm --filter @business-assistant/desktop-react test
corepack pnpm --filter @business-assistant/react-ui test
cargo test --manifest-path apps/desktop-react/src-tauri/Cargo.toml
node scripts/seed-demo-data.mjs --dry-run       # 데모 데이터(SEED_EMAIL/SEED_PASSWORD 필요, --org test)
```

마지막으로 통과를 확인한 테스트 수: API 804, React 905, react-ui 16, Rust 31.

서버 주소 결정(Rust `config.rs`): 실행 환경변수 `BUSINESS_ASSISTANT_API_BASE` → 빌드에 박은 `BUSINESS_ASSISTANT_API_BASE_DEFAULT` → (개발 빌드만) `http://127.0.0.1:8000/api/v1`. 릴리스 빌드는 https만 허용합니다. Storage 호스트 기본 허용은 `*.supabase.co`.

## 6. 아직 안 된 것

### 6-1. 사용자(관리자)가 해야 하는 일 — 배포는 "나중에"로 미룬 상태

1. API 서버 준비(Oracle Cloud Always Free 또는 Lightsail 등 VPS), 도메인과 HTTPS 리버스 프록시.
2. 서버에 `apps/api` 빌드와 `.env` 배치, 서버 재시작 절차 숙지(`docs/guide/admin/deployment.md`).
3. GitHub **Variables**: `BUSINESS_ASSISTANT_API_BASE`(필수, https), 선택 `BUSINESS_ASSISTANT_ADMIN_API_BASE`, `BUSINESS_ASSISTANT_STORAGE_HOST`, `TAURI_UPDATER_PUBKEY`(주의: Secret이 아니라 Variable). **Secrets**: `TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`(서명 키는 `apps/desktop-react`에서 `pnpm tauri signer generate`로 생성, 등록 완료).
4. 첫 릴리스(`v0.x.x` 태그) 시험 설치와 자동 업데이트 확인. 코드 서명 인증서는 선택.
5. 관리자 서버를 띄워 '구독' 메뉴 동작 확인.

### 6-2. 실환경 검증이 안 된 부분 (가장 중요)

작업 환경에 PostgreSQL이 없어 **SQL은 문자열 계약 테스트만** 통과했고 실제 실행은 사용자가 Supabase에 적용한 것이 전부입니다. 아래는 실제 흐름으로 확인되지 않았습니다.

- 수납 → 매출 내역 반영, 지난달 월 마감(042: 마감된 달의 거래·수납·환불은 409), 고객 병합(044: **되돌릴 수 없음**, 보조 고객은 보관 상태로 남음, `archived` 상태 제약 교체가 운영 제약과 충돌하지 않는지 확인 필요), 구성원 추가(045: `auth.users` 조회 보안 정의 함수, `anon`/`public` 실행 권한이 없는지 확인), 파일·사진 업로드/다운로드, 동의서 서명 증빙 해시(043).
- 업데이트 서명·설치·자동 업데이트 전 과정, 릴리스 워크플로 첫 실행.
- 구현을 계속하기 전에 위 항목을 테스트 조직에서 손으로 확인하고, 결과를 `backlog.md`의 `verified`와 changelog에 기록하세요.

## 7. 알려진 제한

- 권한 검사 캐시(`APP_ACCESS_CACHE_TTL_SEC`, 기본 30초)와 로그인 시도 제한은 **단일 인스턴스 메모리 기반**입니다. 서버를 여러 대로 늘리면 SEC-09가 필요합니다.
- 구성원 추가는 이미 가입한 사용자의 이메일만 가능(초대 메일 없음).
- OS 알림은 없고 앱 내 알림 센터만 있습니다.
- 개발 서버는 vite가 `src-tauri`를 감시하지 않도록 설정되어 있습니다(`EBUSY` 방지). 포트 1420 고정.
- 마이그레이션은 **DB 먼저 → API 서버 재시작 → 앱 갱신** 순서. 순서와 멱등성은 `migrations/README.md`.
