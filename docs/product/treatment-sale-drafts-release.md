# 시술 명세 → 결제 초안

2026-09-29 · TRT-003 / SALE-001 · 담당 Codex. 9월28일 시작한 구현을 마무리했다. 두 기능은 실환경 및 전체 범위 미완료로 in-progress를 유지한다. 커밋·배포·운영 DB 변경 없음.

## 사용 흐름

시술관리에서 저장된 완료/중단 시술 선택 → **결제 초안** → 실제 청구 항목·금액·연결할 발행 문서 선택 → **최신 내용 검토** → 확인 체크 → 초안 전달. 매출·지출의 **시술 결제 초안**에서 전달 당시 명세를 조회한다.

- 완료 시술은 기존 시술명·예정 금액을 초기값으로 제시하고 실제 청구 내용을 다시 확인한다. 중단 시술은 항목·금액을 빈칸으로 시작하며 실제 수행 범위와 부분 청구 사유가 필수다. 0원도 허용한다.
- 한 시술에서 수량 1인 항목 하나의 초안만 생성한다. 금액은 소수 둘째 자리까지의 문자열로 전달하며 부동소수점 반올림을 피한다.
- 선택한 문서는 동일 조직·고객·시술의 발행본이어야 한다. 서명 미확인·철회·미연결이면 예외 사유를 필수 기록한다. 예외 기록은 동의 완료나 본인인증을 의미하지 않는다.
- 전달 당시 고객, 시술 버전·담당자, 문서 버전·동의 순번과 상태를 보존한다. 검토 후 원본 변경은 생성 시 차단한다. 전달 후 원본 변경은 기존 초안을 덮어쓰지 않는다.
- 통신 결과불명은 입력을 잠그고 동일 요청으로 재시도한다. 확정 오류/충돌은 입력을 유지한다. 작성 중 종료·이동은 확인하고 처리 중 종료를 막는다. 기존 초안은 읽기 전용이다.
- API는 crm.basic, finance.basic, document.template를 모두 검사한다. 회원은 조회, owner/admin은 생성 가능하며 DB에서도 조직과 역할을 검사한다.

초안은 **미수납 검토 명세**다. 기존 수입 합계·실적·재고·수당에는 반영하지 않는다. 방문 묶음, 제품/회원권 장바구니, 할인, 실제 수납·환불·정정은 후속 범위다.

## 적용 및 실환경 인수

대상 DB의 기존 migration001~020 적용 상태를 확인한 후 `021_treatment_sale_drafts.sql`을 적용하고 새 서버/데스크톱을 함께 사용한다. 이번 작업에서는 운영 DB에 적용하지 않았다.

테스트 고객으로 완료 시술 초안, 중단 시술 0원/부분 청구, 서명·미서명·철회 문서, 회원 읽기, 권한 없는 변경, 다른 조직 접근, 통신 실패 후 동일 재시도, 두 클라이언트 동시 생성, 전달 후 원본 정정을 확인한다. 실제 PostgREST의 JWT/RLS와 전체 migration 체인, 동시 연결 잠금, 화면 배치는 실환경 인수 대상이다.
