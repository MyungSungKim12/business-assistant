# 고객 판매 상품 반품·환불 적용 안내

작성일: 2026-10-08 · 기능: SALE-003 / INV-002 · 상태: 로컬 코드·격리 검증 완료, 실환경 인수 대기

## 적용 순서

사용자가 030 적용을 완료했다고 보고했다. Supabase SQL Editor에서 030 성공 여부를 확인하고, 다음 새 파일만 **한 번** 실행한다.

1. `migrations/031_customer_product_returns.sql`
2. 서버와 데스크톱을 같은 최신 소스 버전으로 재시작한다.
3. 테스트 조직의 유료 상품 판매 건에서 수량 일부 반품, 재입고/폐기 선택, 원영수증 환불을 확인한다.
4. 부분 반품 후 나머지 금액을 전액 환불해도 재고가 중복 복원되지 않는지 확인한다.

031은 이미 적용된 030 뒤에 이어지는 migration이다. 운영 Supabase에는 접속하거나 SQL을 실행하지 않았다.

## 사용 흐름

매출의 방문별 수납 화면에서 **상품 반품**을 연다. 반품할 판매 상품과 원결제 영수증을 선택하고 수량·환불액·사유를 입력한다. 상품 상태에 따라 재입고를 켜거나 끈다. 실제 카드사/은행 환불을 먼저 완료하고 확인 상자에 체크해야 기록할 수 있다.

상품 반품과 결제 환불, 재무 지출, 선택한 경우 재고 입고, 반품 원장을 하나의 DB 트랜잭션으로 기록한다. 반품 수량은 판매 수량에서 기존 반품 수량을 뺀 범위까지 가능하고, 환불액은 원영수증 잔액과 할인 배분 후 해당 상품 수량의 판매액을 넘을 수 없다. SALE-004 할인은 품목별 금액에 비례 배분하고 마지막 품목에 반올림 잔액을 반영한다. 재고 상태가 좋지 않은 반품은 재입고를 끄면 재고에 더하지 않는다.

그 뒤 원거래 잔액까지 전액 환불하면 기존 전체 취소가 나머지 판매 수량만 복원한다. 이미 재입고한 수량은 다시 더하지 않고, 폐기 반품 수량도 재입고하지 않는다. 재시도는 저장된 동일 operation ID를 사용한다.

## 권한과 한계

- owner/admin만 기록할 수 있으며, DB RPC도 조직·역할·원거래·버전·수량·영수증을 재검증한다.
- 현재 현금·카드·이체 영수증에 대한 단일 원결제 환불을 지원한다. 회원권 사용분으로 결제한 상품의 부분 환불과 여러 원결제 수단에 걸친 분할 환불은 지원하지 않는다.
- 외부 PG/카드사/은행 취소, 반품 승인 단계, 공급업체 비용·수당·세금·할인 반대 원장, 마감 후 정정 승인은 별도 작업이다.
- 반품·환불 이력은 불변 원장으로 저장한다. 화면은 누적 반품 수량을 표시하지만 과거 반품 사유·담당자 전체 이력 탐색은 지원하지 않는다.

- 실제 Supabase 적용·다중 세션 동시성·실제 카드/은행 환불·사용자 Windows 육안 인수는 미실행이다.
