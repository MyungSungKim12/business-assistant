# 회원권 사용·차감 적용 안내

작성일: 2026-10-07 · 기능: WAL-002, WAL-004, SALE-002 · 담당: Codex  
상태: 1차 사용 흐름 로컬 구현·검증 완료, 실환경 인수 전 `in-progress`

## 사용할 수 있는 흐름

결제 장바구니에서 고객과 방문을 선택해 청구 항목을 검토 완료한다. **회원권 · 잔여 혜택**을 열면 사용 가능한 고객 회원권과 활성 시술 항목을 선택할 수 있다.

- 금액권: 잔여 금액 안에서 원 단위 사용액을 입력한다.
- 횟수권: 1회를 차감하고 선택한 시술 항목의 아직 적용되지 않은 금액 전체를 방문 결제에 반영한다.
- 복합권: 한 번의 요청에서는 금액 또는 횟수 중 하나를 선택한다.
- 회원권 적용액과 현금·카드·이체 수납액을 합쳐 미수금과 방문 완료 여부를 계산한다.
- 고객 회원권 조회에는 잔액과 변경할 수 없는 사용 내역이 함께 표시된다.

회원권은 이미 판매될 때 매출로 기록된 혜택이므로 사용할 때 새 재무 수입을 만들지 않는다.

## SQL 적용 순서

사용자는 024~026 적용을 완료했다고 보고했다. 027과 028의 운영 DB 적용 여부는 이번 작업에서 확인하거나 변경하지 않았다.

1. [027_catalog_sales.sql](https://github.com/MyungSungKim12/business-assistant/blob/main/migrations/027_catalog_sales.sql)을 적용하지 않았다면 먼저 한 번 실행한다.
2. 이어서 [028_wallet_usage.sql](https://github.com/MyungSungKim12/business-assistant/blob/main/migrations/028_wallet_usage.sql)을 한 번 실행한다.
3. 같은 소스 버전의 서버와 데스크톱을 재시작한다.
4. 별도 테스트 고객으로 회원권 판매·완납 → 새 방문 시술 검토 완료 → 금액권/횟수권 사용 → 잔액·미수금·사용 내역을 확인한다.

028은 기존 발급 잔액을 바꾸거나 과거 방문에 사용 내역을 소급 생성하지 않는다. 서버/앱을 먼저 올린 상태에서 028을 적용하지 않으면 회원권 사용 API가 실패하므로 SQL부터 적용한다.

## 보호 규칙

- owner/admin만 회원권을 사용 처리하며 member는 잔액과 사용 내역만 조회한다.
- 지갑·장바구니·시술 항목의 조직, 고객, 방문 관계를 DB에서 다시 검사한다.
- 유효기간 전·만료 후·잔액 부족·이미 횟수 적용된 시술·다른 고객 지갑은 거부한다.
- 지갑과 장바구니를 잠근 뒤 잔액을 검사해 마지막 1회 또는 마지막 금액이 음수가 되지 않게 한다.
- 사용 원장은 수정·삭제하지 않는다. 작업 ID 재전송은 같은 결과만 반환한다.
- 통신 결과가 불명확하면 복구 정보를 디스크에 보관해 앱 재실행·재로그인 후 같은 요청으로 확인한다. 결과 불명 후 401/403에서도 작업 ID를 지우지 않는다.
