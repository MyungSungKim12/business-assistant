# 공통 품질 게이트

각 기능의 verified는 아래 적용 항목과 메뉴별 인수 조건을 함께 통과했다는 뜻이다. 적용하지 않은 게이트는 이유를 남긴다. 단위 테스트만으로 실연동·복구·운영까지 검증됐다고 표현하지 않는다.

| ID | 게이트 | 통과 증거 |
| --- | --- | --- |
| Q-01 | 조직·권한 경계 | 다른 조직 ID 직접 요청 차단, 읽기 역할의 변경 API 거부, 구독 미허용 상태 확인 |
| Q-02 | 입력·상태 계약 | 필수/길이/날짜/금액 경계, 미지 필드, 허용되지 않는 상태 전이 거부 |
| Q-03 | 저장 일관성 | 다중 필드 작업 중 오류 시 일부 저장 없음; 금전·회차·재고는 동시 요청과 중복 재시도 검증 |
| Q-04 | UI 상태 | 로딩/빈 결과/오류/권한 없음 구분, 중복 클릭 제어, 키보드 이동, 작은 창에서 핵심 행동 접근 |
| Q-05 | 취소·복구 | 변경 전 취소는 무변경; 저장 실패 시 입력 유지; 미저장 이탈 시 선택; 타임아웃 결과 불명확 시 확인 경로 |
| Q-06 | 원장·추적 | 원본 ID·행위자·시각·정정 사유 연결; 확정 기록은 역거래/버전으로 정정; 대사 차이 원인 표시 |
| Q-07 | 시간·금액 | 저장 시각과 지점 표시 시간 구분; 기간 끝 경계; 소수·반올림·환불 배분 정책의 예제 테스트 |
| Q-08 | 민감 데이터 | 최소 권한, 로그 마스킹, 사진/내보내기 접근 제어, 보존·삭제 정책과 철회 처리 검증 |
| Q-09 | 운영 복구 | 오프라인·503·세션 만료·서비스 오류에서 복구; 외부 전송 재시도는 중복 부작용 방지 |
| Q-10 | 실데이터 정직성 | 기본 화면에 샘플 고객·사진·가짜 KPI 없음; 데모는 명시 선택과 표시; 미수집 수치를 0으로 오인시키지 않음 |
| Q-11 | 성능·범위 | 합의한 건수·환경·응답 목표를 기록하고 측정; 페이지/검색/집계가 같은 필터와 데이터 범위를 사용 |
| Q-12 | 회귀·문서 | 관련 자동 테스트, 필요한 화면 확인, 기존 흐름 회귀 확인; 기능 행·검증 기록·변경 이력 일치 |

## 검증 기록 템플릿

- 기능 ID / 범위 / 담당자 / 날짜:
- 커밋과 실행 환경 / 데모·테스트·운영 구분:
- 테스트 명령과 결과 / 실패 사례:
- 메뉴별 인수 조건 결과 / 공통 게이트 결과:
- UI 증거 경로 / 실연동 증거(해당 시):
- 성능 표본 건수·환경·기준·측정치:
- 알려진 제한 / 제외 항목 / 다음 검증:

P0로 제안하는 성능 목표는 고객 10,000명 환경에서 검색 응답 1초 이내, 기본 화면 첫 조회 2초 이내다. 네트워크·장비·데이터 환경을 정한 뒤 채택 여부를 확정한다. 측정하지 않은 목표는 달성값이 아니다.
