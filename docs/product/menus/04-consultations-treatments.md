# 04 상담·시술

목적: 상담 내용·고객 동의·수행 시술·담당자·사후 안내를 연결한다. 상담자는 요청과 주의사항, 시술자는 실제 수행 내용, 관리자는 정정과 품질 이력을 관리한다. 피부 정보는 서비스 기록이며 의료 진단으로 자동 해석하지 않는다.

## 화면과 업무 흐름

좌측 방문/고객 목록, 중앙 상담·시술 단계 폼, 우측 고객 주의사항과 과거 기록이다. 시술 명세·사용 제품·전후 사진·동의 문서·후속 일정 탭을 둔다.

예약 또는 무예약 방문 선택 → 고객 주의사항 확인 → 상담 목표·예상 서비스 입력 → 동의 버전 확인 → 시술 시작 → 실제 서비스/담당/소요/사용량 기록 → 완료 → 결제 초안 전달 → 사후 안내 생성. 시술 완료와 수납 완료는 다른 상태다.

상담 취소는 초안 폐기 또는 취소 기록을 선택한다. 진행 중 중단은 사유·실제 수행 항목을 남기고 부분 청구 판단으로 넘긴다. 완료 기록 정정은 원본 보존과 정정 사유가 필요하다. 사진 업로드 실패는 시술 텍스트 저장 결과와 구분해 재시도한다.

## 의존성과 인수 조건

CRM 프로필/활동, APT 방문, DOC 동의, MED 사진, SALE 명세, INV 사용량, CARE 사후 관리가 연결된다.

- 시술 완료 후 결제 초안 생성이 실패해도 완료 기록은 남고 '결제 전달 대기'에서 재시도할 수 있다. 같은 시술 청구가 중복되지 않는다.
- 진행 중 중단 사례는 실제 수행 항목만 남기고 예약 전체 서비스를 자동 청구하지 않는다.
- 완료 기록 정정 전후가 추적되며 결제/재고 영향은 명시적 정정 절차로 처리된다.
- 사진 접근 권한 없는 사용자는 경로를 알아도 원본에 접근할 수 없다. 사진이 없으면 실제 빈 상태를 보여준다.
- 동의 템플릿을 수정해도 과거 시술에 연결된 문서 내용과 버전은 변하지 않는다.

## TRT-007 검증 기록 — 2026-09-18

**완료 범위:** 로컬 코드·모의 API 검증. 사이드바 `시술관리` 또는 고객관리 `시술관리 열기`로 접근한다. 왼쪽 고객 검색/주의사항, 중앙 이력과 검색, 오른쪽 기록 작성/수정의 3열 화면이다. 서버와 앱의 새 코드를 함께 실행해야 PATCH 수정이 동작한다. 기존 treatment_records 스키마를 사용하며 신규 마이그레이션은 없다.

- 등록·조회·같은 ID 수정·기록 복사 지원. 복사는 오늘 날짜의 미저장 새 기록이며 원본은 그대로 유지한다.
- 시술명/담당자/메모 검색, 분류와 시작·종료일 필터, 이름·전화번호 고객 검색.
- 시술일 필수, 다음 방문일은 시술일 이상, 금액은 미입력 또는 0 이상 1조 미만/소수 두 자리. 금액은 예정 금액이며 수납·매출 자동 반영이 아니다.
- 고객/이력/저장 비동기 처리, 오래된 응답 무시, 중복 저장 클릭 차단, 실패 시 입력 보존, 재조회 지원.
- 고객·기록·메뉴 전환과 앱 종료 시 저장/버리기/취소. 저장을 선택하면 완료 후 다시 이동한다. 읽기 사용자는 조회만 가능하며 서버도 owner/admin 외 쓰기를 거부한다.
- API 수정은 조직·고객·시술 ID를 함께 제한하며 미존재는 404, 저장소 장애는 503. 날짜와 Decimal을 JSON 문자열로 전달한다.

## TRT-002 검증 기록 — 2026-09-18

verified는 로컬 구현/격리 검증 범위다. 신규 시술 준비→진행→완료 또는 중단, 사유 있는 정정과 변경 이력 조회를 구현했다. 기존 자료는 legacy로 표시한다. 상태 변경·편집·정정은 행 잠금, 버전 검사, 동일 작업 재시도 식별, 원본/변경본 스냅샷을 단일 DB 트랜잭션으로 처리한다. 직접 테이블 변경은 차단한다. 감사 기록이 있는 고객/시술 삭제도 FK로 보호한다.

화면은 완료·중단 기록을 읽기 전용으로 열고 정정 모드와 사유 입력을 제공한다. 변경 이력은 기록자 ID/시각/사유/필드 변경 전후를 표시한다. 중단 저장 실패 시 사유를 유지하고, 오래된 비동기 이력 조회가 새 창을 덮어쓰지 않도록 요청을 구분한다. 금액 0도 누락 없이 표시한다.

검증: desktop 117, server/common 143, 격리 PostgreSQL 15개 통과. Ruff/format 전체 통과, mypy 64개 소스 통과. DB 및 API/UI 검토에서 발견한 비동기 조회 경합·중단 사유 유실·0원 표시 문제를 수정하고 회귀 테스트로 확인했다.
