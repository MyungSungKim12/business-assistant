# 09 비용·정산·손익

갱신일: 2026-09-18 · 담당: 제품/구현 담당자 · 현재 판정: 목표 설계, 실운영 검증 전

## 목적과 사용자

사장님과 관리자가 수금·지급·비용을 확인하고 근거 있는 관리손익을 비교한다.

## 화면 구성

오늘 정산/입출금/비용/미지급/관리손익 탭. 집계 금액 클릭 시 원거래 목록과 첨부 증빙으로 이동한다.

## 기능 추적

| --- | --- | --- | --- |

## 필드와 업무 규칙

- expense_id, category, counterparty, amount, incurred_on, due_on, paid_on, evidence_id: 발생/지급 시점을 분리한다.
- settlement_id, expected_amount, actual_amount, fee, difference, matched_payment_ids: 대사 근거를 유지한다.
- cost_basis, allocation_rule_version, reporting_period: 공통 비용 배부 기준을 표시한다.
- 예상·확정·미확인 금액을 구분하며 관리손익을 공식 재무제표나 신고 완료로 표시하지 않는다.

## 정상·취소·실패 흐름

1. 비용 등록 → 증빙/분류 검토 → 승인 → 지급 → 지급 거래 연결.
2. 결제 원장과 입금 내역 불러오기 → 자동 일치 후보 → 차이 검토 → 수동 연결·해제.
3. 보고서에서 비용 배부 기준 확인 → 원거래 검토 → 정정 후 계산 결과와 버전 비교.

## 연동과 단계

SALE 결제/환불, INV 매입·소비 원가, TEAM 수당, 문서/미디어 증빙.

1차는 P0의 실제 업무 흐름과 복구 경로를 검증한다. P1은 기본 데이터와 정정 흐름이 안정된 뒤 구현한다. P2는 외부 연동 계약 또는 충분한 데이터가 확보된 뒤 진행한다. 기존 범용 메뉴/API가 일부 있어도 이 문서의 기능 완료로 간주하지 않는다.

## 인수 조건

- [ ] 수수료를 제외한 입금이 매출 누락으로 잘못 집계되지 않는다.
- [ ] 동일 증빙 중복 등록 후보를 표시하되 검토 전 자동 삭제하지 않는다.
- [ ] 보고서 합계가 원거래 합계와 일치하고 비용이 미입력되면 추정임을 표시한다.
- [ ] 다른 조직 데이터 접근과 권한 없는 변경이 서버에서 거부된다.
- [ ] 빈 상태·로딩·실패·재시도·동시 변경 시 사용자가 현재 상태를 알 수 있다.
