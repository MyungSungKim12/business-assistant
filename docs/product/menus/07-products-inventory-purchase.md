# 07 상품·재고·구매

갱신일: 2026-09-18 · 담당: 제품/구현 담당자 · 현재 판정: 목표 설계, 실운영 검증 전

## 목적과 사용자

판매용·시술용 재고와 거래처 주문을 연결해 품절·과다 사용·유통기한 손실을 줄인다.

## 화면 구성

재고 목록은 판매용/시술용·부족·만료 임박 필터를 제공한다. 품목 상세에 로트별 수량과 입출고 원장, 발주 화면에 거래처별 주문과 부분 입고를 배치한다.

## 필드와 업무 규칙

- product_id, sku, barcode, usage_type, base_unit: SKU는 조직 내 고유하며 판매/시술 겸용을 허용한다.
- purchase_unit, conversion_factor, precision: 1병=500ml 등 환산 계수와 허용 소수점 자릿수를 명시한다.
- lot_id, received_at, expires_at, opened_at, location_id: 재고는 보관 위치·로트 단위로 집계한다.
- movement_id, kind, delta, source_type, source_id, reason: 모든 변동은 원천을 가진다.
- purchase_order_id, supplier_id, ordered_qty, received_qty, unit_cost: 부분 입고와 취소 잔량을 구분한다.

## 정상·취소·실패 흐름

1. 부족 품목 확인 → 거래처별 발주 초안 → 발주 확정 → 부분 입고와 로트 등록 → 잔여 주문 추적.
2. 시술 종료 시 기준 사용량 제안 → 실제 사용량 확인 → 출고 기록. 시술 취소는 실제 소비 여부를 확인해 반영한다.
3. 실사 기준 시점의 장부 수량을 고정 → 실측 입력 → 차이 검토 → 조정 승인.
4. 발주 취소는 미입고 수량에만 적용한다. 이미 입고된 제품은 반품 흐름으로 처리한다.

## 연동과 단계

TRT 사용 재료, SALE 제품 판매/반품, FIN 거래처 지급, APT 예정 수요.

1차는 P0의 실제 업무 흐름과 복구 경로를 검증한다. P1은 기본 데이터와 정정 흐름이 안정된 뒤 구현한다. P2는 외부 연동 계약 또는 충분한 데이터가 확보된 뒤 진행한다. 기존 범용 메뉴/API가 일부 있어도 이 문서의 기능 완료로 간주하지 않는다.

## 인수 조건

- [ ] 500ml 한 병 입고 후 12.5ml를 4회 사용하면 450ml가 남는다.
- [ ] 10개 발주 중 4개 입고 시 미입고 6개와 입고 4개가 구분된다.
- [ ] 실사 중 발생한 출고가 조정과 중복 반영되지 않으며 조정 전후 수량을 설명할 수 있다.
- [ ] 다른 조직 데이터 접근과 권한 없는 변경이 서버에서 거부된다.
- [ ] 빈 상태·로딩·실패·재시도·동시 변경 시 사용자가 현재 상태를 알 수 있다.
