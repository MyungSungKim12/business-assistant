# 01 대시보드

목적: 원장·예약을 근거로 오늘의 우선 업무를 정한다. 원장은 매출·인력·이탈 위험, 매니저는 예약 충돌·미수금, 직원은 본인 예약·후속 업무를 본다. 역할별 보기와 지점·일자 필터를 상단에 고정한다.

## 화면과 흐름

상단은 일자·지점·집계 기준·마지막 갱신 시각, 중단은 오늘 예약/방문/수납/미수금 카드, 하단은 시간순 일정과 처리 필요 목록이다. 지표 클릭은 동일 필터의 원본 목록으로 이동한다. 빈 예약은 등록 행동, 집계 오류는 재시도 행동을 제공한다.

출근 → 오늘 범위 확인 → 지연 예약이나 미완료 업무 열기 → 해당 메뉴에서 처리 → 복귀 후 재집계한다. 기간 변경 중 취소하면 이전 범위를 유지한다. 일부 원천 조회 실패 시 성공한 카드만 표시하고 실패 카드에는 '집계 불가'와 재시도를 표시한다. 오래된 캐시는 기준 시각을 표시하며 최신 값처럼 취급하지 않는다.

## 기능

| ID | 우선 | 상태 | 요구사항 |
| --- | --- | --- | --- |
| DASH-001 | P0 | planned | 역할·지점·일자 범위와 최근 갱신 시각 표시 |
| DASH-002 | P0 | planned | 예약·방문·수납·미수금 카드와 원본 이동 |
| DASH-003 | P0 | planned | 지연 예약, 미완료 시술, 정산 차이, 후속 업무 큐 |
| DASH-004 | P0 | planned | 부분 장애·미수집·빈 데이터·오래된 캐시 구분 |
| DASH-005 | P1 | planned | 전일·전주 비교와 직원별 개인화 |

## 데이터와 집계 규칙

| 필드 | 규칙 |
| --- | --- |
| organization_id, branch_id | 서버 허용 범위 내 선택; 전체 지점은 별도 권한 |
| business_date, timezone | 지점 영업일 기준; 자정 이후 운영의 날짜 정책 필요 |
| scheduled_count, arrived_count | 예약 상태별 건수; 취소 제외 규칙과 무예약 방문 포함 여부 명시 |
| collected_amount | 결제 완료액에서 기간 내 환불액 차감; 시술 매출과 다른 지표 |
| receivable_amount | 확정 청구액 중 미수 잔액; 기간 기준은 잔액 기준일 |
| source_status, calculated_at | 원천별 성공/실패/미수집과 계산 시각 |
| action_id, due_at, assignee_id | 업무 중복 방지 키, 기한, 처리 담당자 |

## 의존성과 인수 조건

APT의 상태, SALE의 수납 원장, FIN의 대사, CARE의 후속 기한, NOTI의 내부 알림에 의존한다. LAB과 동일 지표 정의를 사용한다.

- DASH-002: 같은 날짜·지점에서 카드 건수/금액과 원본 목록의 총합이 같고 취소·환불 사례에서도 대사된다.
- DASH-001/003: 직원은 허용된 예약·업무만 보며 다른 직원 상세로 직접 이동해도 서버가 범위를 검사한다.
- DASH-004: 결제 조회만 실패하면 예약 카드는 유지되고 결제 카드는 0원 대신 오류 상태를 표시한다.
- DASH-005: 비교 기준 기간의 데이터가 없으면 증감률을 임의 계산하지 않는다.

## 단계와 검증

1차는 실제 연결된 원천만 노출한다. 2차에 비교·개인화, 3차에 이상 징후를 추가한다. 현황: 카탈로그에 대시보드 메뉴가 있음을 확인했으나 위 업무 지표는 검증하지 않았고 모두 planned다. 검증 기록은 [공통 양식](../quality-gates.md)을 따른다.
