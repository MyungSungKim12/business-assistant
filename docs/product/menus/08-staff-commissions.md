# 08 직원·근무·수당

갱신일: 2026-09-18 · 담당: 제품/구현 담당자 · 현재 판정: 목표 설계, 실운영 검증 전

## 목적과 사용자

직원 배치·업무 인수인계·성과 배분과 수당 계산을 투명하게 관리한다.

## 화면 구성

직원 목록/근무표/실적/수당 탭을 둔다. 개인 상세에는 가능 시술과 교육 이력, 관리자 화면에는 수당 규칙과 확정 내역을 배치한다.

## 필드와 업무 규칙

- staff_id, membership_id, employment_status, available_services: 직원 기록과 로그인 계정을 구분한다.
- shift_id, start_at, end_at, break_minutes, location_id: 근무·휴무 충돌을 검증한다.
- rule_version, effective_from, category, tiers, basis: 판매액/할인 후 금액/수금액 중 계산 기준을 명시한다.
- commission_line_id, sale_line_id, allocation, amount, adjustment_reference: 소급 정정도 원천을 가진다.

## 정상·취소·실패 흐름

1. 관리자가 수당 규칙을 시행일과 함께 등록 → 거래 확정 시 적용 규칙 기록 → 기간 집계 → 검토 → 확정.
2. 환불이 생기면 확정 수당을 덮어쓰지 않고 다음 정산 또는 별도 정정으로 연결한다.
3. 직원 퇴사 → 접근 차단 → 예약 담당자 재배정 → 미완료 업무 인계. 과거 거래의 담당자 이름은 보존한다.

## 연동과 단계

설정 모듈 역할/조직, APT 직원 일정, SALE 담당 배분, TRT 수행 기록, FIN 지급.

1차는 P0의 실제 업무 흐름과 복구 경로를 검증한다. P1은 기본 데이터와 정정 흐름이 안정된 뒤 구현한다. P2는 외부 연동 계약 또는 충분한 데이터가 확보된 뒤 진행한다. 기존 범용 메뉴/API가 일부 있어도 이 문서의 기능 완료로 간주하지 않는다.

## 인수 조건

- [ ] 두 직원 배분 합계가 규칙에 맞고 수당 명세서에서 거래별 계산 근거가 열린다.
- [ ] 다음 달 규칙 변경은 전월 확정 수당을 바꾸지 않는다.
- [ ] 읽기 권한 없는 직원은 화면뿐 아니라 API로도 다른 직원의 수당을 조회하지 못한다.
- [ ] 다른 조직 데이터 접근과 권한 없는 변경이 서버에서 거부된다.
- [ ] 빈 상태·로딩·실패·재시도·동시 변경 시 사용자가 현재 상태를 알 수 있다.
