# 03 예약

목적: 고객·직원·공간·시간을 연결하여 중복 예약과 누락 방문을 줄인다. 접수는 예약 배정, 직원은 본인 일정과 방문 처리, 관리자는 예외 승인·영업 정책을 담당한다.

## 화면과 업무 흐름

일/주 달력과 직원별 열, 대기 목록, 빠른 고객 검색, 예약 상세 패널로 구성한다. 공간·장비가 필요한 서비스는 리소스 행을 함께 표시한다. 색상 외에도 상태 텍스트를 제공한다.

고객 선택/빠른 등록 → 서비스·직원·시작 시각 선택 → 소요 시간과 여유 시간 자동 제안 → 충돌 검사 → 예약 확정 → 확인 안내 → 방문 체크인 → 시술 전달. 외부 발송 실패가 예약 자체를 취소하지 않는다. 일정 변경은 기존 슬롯과 새 슬롯을 한 전환으로 처리한다.

예약 취소는 사유·취소 주체를 기록하고 슬롯을 반환한다. 노쇼는 영업 정책에 따라 지정하며 자동 수수료 결제를 하지 않는다. 저장 실패 시 입력을 보존하고 충돌 발생 시 대체 슬롯을 제시한다. 드래그 이동 취소는 원래 시간을 유지하며 서버 거절 시 원래 위치로 되돌린다.

## 데이터·규칙

| 필드 | 규칙 |
| --- | --- |
| customer_id, branch_id | 필수; 보관 고객 신규 예약은 정책 확인 후 복원 유도 |
| service_items | 서비스 ID·당시 이름·소요 시간 스냅샷; 변경 시 예약 시간 재평가 |
| employee_id, resource_ids | 활동 직원·해당 지점 리소스; 담당 미정 예약은 별도 대기 상태 |
| start_at, end_at, buffer_minutes | 종료>시작; 시간대 포함; 점유 구간은 버퍼 포함 |
| status, cancellation_reason | allowed transition 표를 서버 계약으로 고정; 취소 사유 필수 |
| source, external_id | 전화/방문/온라인 등; 외부 ID는 채널 내 중복 방지 |
| version, updated_by | 동시 편집 버전; 오래된 저장은 충돌 응답 |

슬롯 경계는 `[시작, 종료)`로 정의한다. 직원 휴식·매장 휴무·서비스 필요 자원을 모두 검사한다. 관리자 예외 허용은 명시 권한과 사유가 있어야 하며 조용히 충돌을 무시하지 않는다.

## 의존성과 인수 조건

CRM 고객, TEAM 근무·직원, SETTINGS 서비스/시간 정책, TRT 시술, MKT/INT 발송에 연결한다. 기존 일정·할 일 CRUD는 예약 자원 스케줄러 완성 근거가 아니다.

- 같은 직원의 같은 슬롯을 동시에 확정하면 하나만 성공하고 다른 요청은 최신 충돌 정보를 받는다.
- 시술 60분+버퍼 10분인 예약 뒤 60분 지점 예약은 거부되고 70분 지점은 허용된다.
- 변경 실패·취소 시 이전 슬롯이 유지되며 고객에게 잘못된 확정 메시지가 발송되지 않는다.
- 취소/노쇼/방문 상태별 가능한 행동을 검증하고 완료된 예약을 임의 삭제할 수 없다.
- 무예약 방문은 출처를 기록해 고객·시술로 이어지며 예약 건수와 혼동되지 않는다.

## 단계

1차 단일 지점 내부 예약, 2차 대기·반복·안내, 3차 외부 채널.

## 2026-10-08 구현·검증 기록

- `034_appointments.sql`: 최소 직원/서비스 마스터, 서비스 당시 소요/버퍼 스냅샷, 예약 생성·변경, 취소 사유, 서버 상태 전이, 방문 시 판매 장바구니 동시 생성. API와 일정 화면의 예약 탭을 연결했다. 권한 코드는 기존 `task.basic`으로 통일했다.
- 로컬 격리 DB `node scripts/db-tests/appointments.mjs`: 버퍼 60+10분 경계, 타 직원 동일 시간, 멱등 재시도와 다른 입력 충돌, 오래된 버전, 방문 1회와 장바구니 1회, 상태 전이, 취소 후 슬롯 반환, 역할·조직·직접 쓰기 차단 통과. 서버 API 및 Qt 화면 단위 테스트 통과.
- 방문 처리된 예약에서 해당 고객의 시술관리 화면을 여는 버튼을 추가하고, 방문 전에는 열리지 않도록 Qt 테스트로 확인했다. 이는 고객 선택 화면 진입이며 시술 원장 자동 생성은 아니다.
- `037_appointment_availability.sql`: 담당자별 요일 근무시간과 휴무 등록·취소, 버전 충돌과 멱등 재시도, 기존 예약 보호, 근무시간 밖·휴무 중 예약 차단을 추가했다. 일정 화면의 **근무시간·휴무**에서 관리한다. 기존 근무표가 없는 담당자는 이전 동작을 유지한다.
- **남은 범위:** 공간·장비 충돌, 지점 모델, 관리자 예외 승인, 대체 슬롯, 시술 원장 자동 시작, 별도 방문 완료 연동은 미구현이다. 따라서 APT-001~004 모두 `verified`가 아니다. 사용자는 034~036 적용을 보고했으며 신규 037의 실제 Supabase 적용 및 Windows 화면 인수는 대기한다.
