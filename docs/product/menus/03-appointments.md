## 화면과 업무 흐름

일/주 달력과 직원별 열, 대기 목록, 빠른 고객 검색, 예약 상세 패널로 구성한다. 공간·장비가 필요한 서비스는 리소스 행을 함께 표시한다. 색상 외에도 상태 텍스트를 제공한다.

고객 선택/빠른 등록 → 서비스·직원·시작 시각 선택 → 소요 시간과 여유 시간 자동 제안 → 충돌 검사 → 예약 확정 → 확인 안내 → 방문 체크인 → 시술 전달. 외부 발송 실패가 예약 자체를 취소하지 않는다. 일정 변경은 기존 슬롯과 새 슬롯을 한 전환으로 처리한다.

예약 취소는 사유·취소 주체를 기록하고 슬롯을 반환한다. 노쇼는 영업 정책에 따라 지정하며 자동 수수료 결제를 하지 않는다. 저장 실패 시 입력을 보존하고 충돌 발생 시 대체 슬롯을 제시한다. 드래그 이동 취소는 원래 시간을 유지하며 서버 거절 시 원래 위치로 되돌린다.

## 의존성과 인수 조건

CRM 고객, TEAM 근무·직원, SETTINGS 서비스/시간 정책, TRT 시술, MKT/INT 발송에 연결한다. 기존 일정·할 일 CRUD는 예약 자원 스케줄러 완성 근거가 아니다.

- 같은 직원의 같은 슬롯을 동시에 확정하면 하나만 성공하고 다른 요청은 최신 충돌 정보를 받는다.
- 시술 60분+버퍼 10분인 예약 뒤 60분 지점 예약은 거부되고 70분 지점은 허용된다.
- 변경 실패·취소 시 이전 슬롯이 유지되며 고객에게 잘못된 확정 메시지가 발송되지 않는다.
- 취소/노쇼/방문 상태별 가능한 행동을 검증하고 완료된 예약을 임의 삭제할 수 없다.
- 무예약 방문은 출처를 기록해 고객·시술로 이어지며 예약 건수와 혼동되지 않는다.

## 2026-10-20 APT-20 지점 관리

예약 화면의 지점 필터는 선택한 지점의 담당자와 공간·장비만 보여준다. **지점 관리**에서 owner/admin은 지점을 만들고 담당자 또는 자원을 옮길 수 있다. 예정 예약과 충돌하면 DB가 이동을 거부하며 먼저 예약을 재배정해야 한다. SQL 073~074, API와 React 화면은 구현했고 집중 테스트를 통과했다. 실 Supabase 적용·기존 지점 의미 확인 전까지 in-progress다. [작업·검증·제한](../audits/2026-10-20-appointment-branches.md).

058까지 적용했다는 사용자 보고는 있으나 059는 미적용이다. 이번 확인에서는 API 예약 테스트 7건, 예약·파일 화면 테스트 50건, API/React 타입 검사를 통과했다. SQL은 원격 Supabase에서 실행하지 않았고, 실계정의 역할·동시 예약·자원 충돌을 포함한 업무 왕복 검증은 남아 있다. 반복 예약, 알림톡/SMS, 공개 온라인 예약은 별도 후속 기능이다.
