# 12 분석·경영 실험실

갱신일: 2026-09-18 · 담당: 제품/구현 담당자 · 현재 판정: 목표 설계, 실운영 검증 전

## 목적과 사용자

사장님이 실적의 원인을 확인하고 가격·채용·패키지 변경안을 가정을 바꿔 비교한다.

## 화면 구성

운영 지표/이익 누수/운영 리허설/성장 실험/품질 연구 탭. 모든 결과에 데이터 기간, 필터, 가정, 계산 버전과 원천 연결을 표시한다.

## 필드와 업무 규칙

- metric_id, definition_version, numerator, denominator, exclusions: 지표 정의를 문서와 화면에 함께 제공한다.
- scenario_id, baseline_period, assumptions, capacity_constraints, result_range: 예측은 확정 실적과 별도 저장한다.
- experiment_id, assignment_rule, outcome_window, sample_size: 비교군 배정과 관측 기간을 보존한다.
- 데이터 누락·작은 표본·외부 요인의 영향을 표시한다. 사진만으로 의학적 효과를 판정하지 않는다.

## 정상·취소·실패 흐름

1. 기준 기간 선택 → 데이터 누락 확인 → 시나리오 복제 → 가정 수정 → 결과 범위 비교 → 저장.
2. 시나리오 저장은 실제 가격·근무표·회원권 상품을 변경하지 않는다. 운영 반영은 해당 메뉴의 별도 검토 흐름으로 보낸다.
3. 실험 대상/비교군 확정 → 실행 → 관측 기간 종료 → 결과 및 한계 확인 → 운영 규칙 반영 검토.

## 연동과 단계

CRM 재방문, APT 자원·점유, TRT 소요·평가, SALE 수익, WAL 제공 부담, INV 비용, TEAM 근무, FIN 손익.

1차는 P0의 실제 업무 흐름과 복구 경로를 검증한다. P1은 기본 데이터와 정정 흐름이 안정된 뒤 구현한다. P2는 외부 연동 계약 또는 충분한 데이터가 확보된 뒤 진행한다. 기존 범용 메뉴/API가 일부 있어도 이 문서의 기능 완료로 간주하지 않는다.

## 인수 조건

- [ ] 같은 데이터·규칙·가정으로 재계산하면 같은 결과가 나온다.
- [ ] 예약 수용량보다 큰 매출 시나리오는 필요한 추가 자원을 함께 표시한다.
- [ ] 표본이 적거나 비교군이 없을 때 인과적 효과를 확정해서 표현하지 않는다.
- [ ] 다른 조직 데이터 접근과 권한 없는 변경이 서버에서 거부된다.
- [ ] 빈 상태·로딩·실패·재시도·동시 변경 시 사용자가 현재 상태를 알 수 있다.
