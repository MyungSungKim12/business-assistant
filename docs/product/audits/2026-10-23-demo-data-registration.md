# QA-DATA-01 테스트 매장 데모 데이터 실제 등록

2026-10-23 · 등록 범위 verified. 전체 기능 운영 인수는 별도다.

사용자의 직접 등록 승인에 따라 연결된 Supabase `business-assistant`를 먼저 조회하고 `test` 조직(`cfe8bf07-798a-4194-8bdd-0cb1b3c8df57`)만 대상으로 했다. 기존 일반 고객과 그 사진/메모를 데모로 덮어쓰지 않았다.

## 수행

- 기존 API 시드로 누락된 담당자·근무·휴무·자원·수납/환불/반품과 예약 시나리오를 채웠다. 기존 `[데모]` 고객·상품·시술·문서 등은 재사용했다.
- 자원이 없는 기존 예약 때문에 필수 자원 설정이 충돌하는 경우 기존 예약을 보존했다. 실제 근무/휴무에 맞춰 예약일을 조정하고 노쇼 사유를 전달하도록 시드를 보완했다. SQL로 업무 제약을 우회하지 않았다.
- `scripts/seed/enrich-demo-data.mjs`: 고객 메모/태그 10명, 활동 30건, 합성 고객 사진 10건, 같은 고객의 시술 사진 연결 10건, 오늘/향후 예약 10건 추가. AI 인물 3종을 반복 사용하고 사진/설명에 합성 표식을 붙였다. 실제 시술 효과를 의미하지 않는다.
- 사진 10건 모두 signed download URL로 Storage 본문을 내려받아 확인했다. 기존 고객의 실제 전화번호를 새 데모 고객에 복제하지 않았다.

| 데모 범위 | 건수 |
| --- | ---: |

| 고객 사진 | 11 (신규 합성 10 + 기존 1) |
| 신규 시술 사진 연결 | 10 |
| 신규 고객 활동 | 30 |
| 방문 / 장바구니 | 각각 11 |
| 수납 / 환불 | 10 / 2 |
| 회원권 지갑 | 2 |
| 상품 / 할 일 / 수입·지출 / 문서 / 담당자 | 각각 10 |

## 검증

- 기존 전체 시드 실행 후 충돌을 수정하고 `node scripts/seed-demo-data.mjs --org test --yes --only appointments`로 예약 6영역 성공/실패 0 확인.
- `node scripts/seed/enrich-demo-data.mjs`: customerNotes=10, activities=30, photos=10, treatmentPhotos=10, appointments=10, verifiedPhotos=10.
- Supabase 읽기 전용 집계로 건수 재확인. `pnpm --dir apps/api exec vitest run src/seed-demo-data.test.ts`: 15 tests 통과. 새 스크립트 구문 검사 통과.
- 계정/토큰은 기존 환경 설정에서 메모리로만 읽었으며 출력/새 파일/문서에 저장하지 않았다. 이미지 자산은 `scripts/seed/assets`에 보관했다. 커밋/푸시와 스키마 변경 없음.

앱 새로고침 후 `[데모]` 고객으로 확인한다. 전화 수신 시험은 실제 발신 번호가 해당 고객에 등록돼 있어야 하고 휴대폰 번호부 재동기화가 필요하다. 기존 번호와 중복되면 중복 고객 선택으로 표시된다. 전체 운영 테스트는 하지 않았다.
