# 예약에서 고객·시술·수납으로 이동

2026-10-19 · APT-004 / 최초 소스 감사 F09의 화면 진입 연결 보완.

## 이번에 반영한 동선

- 예약 상세의 **고객 정보**는 해당 고객을 선택한 고객관리 화면으로 이동한다.
- **시술 이력**은 해당 고객의 시술 화면을 연다. 고객을 찾지 못하면 다른 고객으로 대체하지 않고 오류를 안내한다. 시술·청구 초안을 자동 생성하지 않는다.
- 방문 처리 또는 완료 상태의 **수납 장바구니**는 해당 예약 ID와 고객 ID로 기존 방문을 조회하고 그 방문의 장바구니를 연다. 매출 기능 권한이 없는 경우 진입 버튼을 연결하지 않는다. 구성원은 기존 조회 권한만 유지한다.
- 기존 메뉴 이동과 동일하게 작성 중 입력·처리 상태 보호를 거친다. 시술 화면에서도 저장 중에는 공통 이동 보호를 요청한다.

## 안전 규칙

방문이 없거나 여러 건이거나 취소되어 있으면 자동으로 새 방문을 생성하지 않는다. 오류를 안내하고 같은 예약을 다시 확인할 수 있다. 조직·예약·고객 연결을 API와 화면에서 검증하고, 열린 장바구니의 조직·방문·고객 연결도 확인한다. API의 기존 CRM·재무 기능/역할 검사는 유지한다. 조회 실패를 수납·시술·방문 생성으로 대체하지 않는다.

예약 상태 변경, 시술 완료, 청구 초안 담기, 장바구니 검토, 실제 수납은 별개다. 이번 이동 버튼이 이 상태들을 자동 확정하지 않는다.

## SQL 상태

사용자가 **060까지 실행 완료**했다고 보고했다. 원격 DB를 직접 조회해 확인한 것은 아니다. 이번 변경은 기존 방문 조회 필터와 화면 연결을 사용하므로 **061 등 새 SQL은 없다.**

## 남아 있는 범위

APT-004 / F09는 **in-progress**를 유지한다. 시술 원장에 예약·방문 FK를 직접 도입하거나, 예약 서비스·담당자를 시술 초안으로 변환하고 명시적으로 청구에 연결하는 기능은 별도 후속이다. 현재 시술 이력 이동은 고객 문맥을 전달하며, 특정 예약에서 시술이 시작되었다는 원장 연결을 새로 기록하지 않는다.
