# INV-11 매입 단위 환산과 원가 정밀도

## 구현 범위

- 상품별 매입 단위와 그 단위에 포함된 재고 기본 단위 수량을 관리한다. 예를 들어 재고 기본 단위 `개`, 매입 단위 `박스`, 환산 수량 12이면 1박스 입고 시 재고 12개를 반영한다.
- 발주 품목은 발주 생성 순간의 매입 단위와 환산 수량을 스냅샷으로 보관한다. 이후 상품 환산 설정을 바꿔도 기존 발주 입고량은 바뀌지 않는다.
- 발주 입력·입고 화면에 구매 단위와 기본 재고 환산량을 표시한다. 발주 수량과 매입 단가는 발주 단위 기준이며 재고 수량은 기본 단위의 정수로 유지한다.
- 로트·재고 원장의 매입 단가는 소수점 6자리까지 저장해 발주 단가를 기본 단위 원가로 나눌 때 반올림 오차를 줄인다. 회원권은 환산 단위가 없으며 기본 1:1로 제한한다.

## 검증

- `node scripts/db-tests/purchase-orders.mjs`: 통과. 2박스×3개 환산, 1박스 입고로 기본 재고 3개 증가, 박스당 1,000원에서 개당 원가 333.333333 스냅샷, 기존 1:1 발주, FEFO·유통기한·권한·재시도를 확인했다.
- `pnpm --filter @business-assistant/api test -- src/modules/catalog/catalog.test.ts`: 52개 통과. 환산 설정 전달, 기본값, 잘못된 환산 거부, 소수 원가 응답을 확인했다.
- `pnpm --filter @business-assistant/desktop-react test -- src/features/catalog/catalog.test.tsx src/features/catalog/PurchaseOrdersDialog.test.tsx`: 36개 통과.
- API 빌드와 React 빌드 통과. React 빌드에 500KB 초과 청크 안내가 남아 있다.

## 적용 상태와 제한

- SQL 084는 격리 PGlite에서 실행·재실행 검증했으나 Supabase에는 적용하지 않았다. 사용자가 보고한 마지막 적용 번호 065 기준으로 066~084를 순서대로 적용해야 한다.
- 기존 상품은 기존 판매/재고 단위를 그대로 기본 매입 단위로 두고 1:1 환산한다. 기존 발주 품목도 1:1로 보정하며 과거 실제 포장 단위는 추정하지 않는다.
- 상품의 환산 설정 변경은 향후 발주에만 적용된다. 기존 발주 스냅샷은 유지된다.
- 실 Supabase 적용, 실 매장 발주/입고, 실제 ERP 원가 보고 대사는 아직 확인하지 않았다.
