# N1030-10 / INV-009 재고 입력 단축

기준일: 2026-11-03  
상태: 코드·집중 검증 범위에서 verified. 실제 매장 스캐너/발주서/로트 입력 인수는 남아 있다.

## 목적과 의존성

- 기존 INV-001/002/003/004/11 기능을 새 원장으로 대체하지 않고 화면 입력을 연결한다.
- 기존 바코드 정확 일치 검색은 스캔한 상품을 열어 입고·재고 변동 입력을 이어간다. 재고 실사 표에는 바코드 스캐너 입력을 추가해 한 번 스캔할 때마다 해당 상품의 실사 수량을 1개 올린다.
- 안전재고보다 보유량이 낮은 활성 실물 상품에 대해 부족 수량을 매입 단위로 올림 계산해 발주 입력 초안을 미리 채운다. 이는 재고나 발주를 자동 저장하지 않는다.

## 구현 결과

- 실사 스캔은 상품 바코드를 정확히 일치시킨다. 미등록/중복 코드, 잘못 입력된 실사 수량, 허용 한도 초과는 수량을 임의 변경하지 않고 안내한다. 이미 입력한 수량과 여러 번 스캔한 수량을 합산한다.
- 안전재고 발주 제안은 상품별 기준을 사용하고 기준이 없으면 현재 기본값 5개를 쓴다. 비활성·회원권·기준 충족 상품은 제외한다. 부족 수량을 매입 포장 단위로 올림해 수량과 발주 후 예상 재고를 메모로 보여준다.
- 제안 화면에서 공급처·수량·매입 단가를 사람이 검토한다. 확인되지 않은 원가는 빈칸이며 비용을 임의로 0원 처리하지 않는다. 실제 발주 초안 저장은 별도 버튼을 누른 뒤에만 일어난다.
- 현재 제안 계산은 on-hand 재고와 안전재고만 사용한다. 기존 발주 중 미입고 잔량은 차감하지 않는 점을 화면에 표시한다. 현재 데이터 구조에 상품별 기본 공급처가 없어 공급처는 사용자가 고른다.
- 입고는 기존 `receiveStock`/구매 주문 입고 경로, 실사/조정은 기존 `changeStock` 원장과 상품 버전 검사를 사용한다. FEFO 로트 배분/원가 스냅샷 로직을 바꾸는 SQL은 추가하지 않았다.

## 남은 인수

- 실제 USB HID 스캐너의 접미 키(Enter), 여러 바코드 라벨, 실물 매입 포장 단위 입력을 매장에서 확인해야 한다.
- 기존 미입고 발주 수량을 자동 차감하지 않으므로 제안 수량은 사용자가 발주 내역을 대조한 뒤 확정해야 한다. 공급처별 매입 단가 자동완성/상품별 대표 공급처는 모델에 없다.
- 입고 시 로트 코드·유통기한·확인된 매입 단가가 필요한 상품에서 실제 입력과 FEFO 잔량 변화가 맞는지 운영 데이터로 검산하지 않았다.
