# WAL-11 사용하지 않은 회원권 양도

기록일: 2026-10-20 · 상태: in-progress · Supabase 적용 전

## 범위

- `075_wallet_transfer.sql`은 `owner_version`, 이전/새 고객·사유·작업자·요청 키가 있는 불변 양도 원장을 추가한다.
- owner/admin만 같은 조직의 활성 고객에게 양도할 수 있다. 미사용·활성·발급 잔액 일치 조건을 DB가 재검사한다. 사용 이력 또는 환불 이력이 있거나 정지된 지갑은 양도할 수 없다.
- 고객 회원권 화면에 양도 대상을 선택하고 사유를 기록하는 동선을 추가했다. 목록에서 양도된 지갑은 이전 고객에게 더 이상 표시되지 않고 새 고객에게 표시된다. 지갑 이력 RPC에 양도 이벤트를 포함한다.
- 같은 작업 ID의 재요청은 같은 결과를 반환하고 다른 입력으로 재사용하면 충돌한다.

## 검증

- `npm run test:wallet-transfer --prefix scripts/db-tests`: PGlite 9개 그룹 통과. 양도, 재시도, 상태·역할 경계, 다른 고객의 잘못된 양도 거절과 이력 포함을 검사했다.
- `pnpm --filter @business-assistant/api test -- catalog.test.ts`: 51개 통과.
- `pnpm --filter @business-assistant/desktop-react test -- catalog.test.tsx`: 34개 통과.
- API·React 빌드 통과. 전체 테스트와 실제 Supabase/Windows 앱 확인은 하지 않았다.

## 제한과 다음 단계

SQL 075는 029 환불 및 035 회원권 수명주기 이후에 적용해야 한다. 기존 029 경로는 방문의 결제 원천을 전부 환불할 때 미사용 회원권을 함께 원복한다. 사용된 회원권만 따로 부분 환불하는 동선은 없다. 할인 배분·남은 가치·수당·재무 역분개 기준이 정해지지 않아 계산하지 않았고 외부 결제 취소도 실행하지 않는다. 이 정책과 별도 감사 화면을 정하고 실계정에서 양도·권한·이력 흐름을 인수해야 WAL-11을 verified로 바꿀 수 있다.

## 후속 정정 — 안전한 금액권 잔액 환불 범위

사용된 회원권 환불은 SQL 087/092에서 실제 외부 환불액과 회수 혜택을 별도 입력해 원장에 기록한다. 할인 불일치·횟수/복합권 잔여 가치 산정은 자동 계산하지 않으며, 관리자가 매장 정책에 따라 각 값을 정한다. 자세한 전제와 제한은 [회원권 환불 감사 기록](2026-10-20-wallet-partial-refund.md)에 있다.
