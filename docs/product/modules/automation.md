# 업무 자동화

갱신일: 2026-09-18 · 상태: planned

## 목적·진입점

매장 이벤트를 조건에 맞는 후속 작업으로 연결하고 실행 내역을 추적한다. 업무 화면에서 진입하고 관리자용 설정은 공통 설정에 둔다.

## 기능 추적

| ID | 우선 | 상태 | 범위 |
| --- | --- | --- | --- |
| AUTO-001 | P0 | planned | 이벤트·조건·행동 규칙과 활성/정지 |
| AUTO-002 | P0 | planned | 실행 전 예상 대상 시뮬레이션 |
| AUTO-003 | P1 | planned | 중복 방지·재시도·실패 처리함 |
| AUTO-004 | P1 | planned | 규칙 버전별 실행 근거와 중지 기능 |

## 데이터 계약

rule_id, version, event_type, conditions, action_type, run_id, source_event_id, status, attempts, next_retry_at. 식별자에는 조직 경계를 적용한다. 기존 API에 없는 필드는 구현 전에 계약과 마이그레이션을 검토한다.

## 업무·복구 흐름

규칙 초안 → 테스트 대상 확인 → 활성화 → 이벤트 발생 → 조건 재검증 → 실행/기록. 규칙 중지 시 대기 작업을 취소하고 이미 실행된 외부 행동은 별도 정정한다.

## 인수 조건

- [ ] 같은 이벤트 두 번 수신에도 한 번만 실행된다. 실행 시점의 수신 동의·예약 상태·권한을 다시 검사한다.
- [ ] 오류·권한 부족·취소 결과를 사용자에게 표시하고 작성 중 입력을 보존한다.
- [ ] 성공 재시도·중복 이벤트·다른 조직 접근 사례를 테스트한다.

## 단계·검증 기록

소비 메뉴의 P0 흐름에 필요한 최소 기능부터 제공하고, 확장 기능은 별도 검증한다. 2026-09-18 문서 작성; 실환경 검증 없음. 기존 범용 API 존재는 이 문서의 전체 기능 완료 증거가 아니다. 상태 변경 시 [변경 이력](../changelog.md)에 증거와 제한을 기록한다.
