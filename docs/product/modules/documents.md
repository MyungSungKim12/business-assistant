갱신일: 2026-09-28 · 상태: DOC-001~004 in-progress (코드 구현, 실행 검증 대기)

## 목적·진입점

상담서·동의서·안내서·견적서의 템플릿과 고객별 발행본을 관리한다. 업무 화면에서 진입하고 관리자용 설정은 공통 설정에 둔다.

| --- | --- | --- | --- |
| DOC-001 | P0 | in-progress | 템플릿 초안/게시/폐기와 버전 관리 |
| DOC-002 | P0 | in-progress | 고객·시술 데이터 미리 채움과 발행 전 검토 |

| DOC-004 | P1 | in-progress | 서명·교부·철회 이력과 접근 권한 |

## 데이터 계약

template_id/version, document_id, customer_id, source_id, status, issued_at, signer_reference, content_hash. 식별자에는 조직 경계를 적용한다. 기존 API에 없는 필드는 구현 전에 계약과 마이그레이션을 검토한다.

## 업무·복구 흐름

게시된 템플릿으로 초안 생성 → 담당자 검토 → 발행/서명 → 고객 기록 연결. 수정 시 신규 버전/정정본을 만들고 발행본을 덮어쓰지 않는다.

## 인수 조건

- [ ] 서식 수정 후에도 이전 고객 발행본의 내용이 변하지 않는다. 필수 고객값 누락 시 발행하지 않고 누락 항목을 표시한다.
- [ ] 오류·권한 부족·취소 결과를 사용자에게 표시하고 작성 중 입력을 보존한다.
- [ ] 성공 재시도·중복 이벤트·다른 조직 접근 사례를 테스트한다.

## 단계·검증 기록

소비 메뉴의 P0 흐름에 필요한 최소 기능부터 제공하고, 확장 기능은 별도 검증한다. 2026-09-18 문서 작성; 실환경 검증 없음. 기존 범용 API 존재는 이 문서의 전체 기능 완료 증거가 아니다. 상태 변경 시 [변경 이력](../changelog.md)에 증거와 제한을 기록한다.

## DOC-001 구현 기록 — 2026-09-22

담당 Codex, 미커밋. [실행 계획](../../superpowers/plans/2026-09-22-document-versions.md).
초안 저장·게시·새 버전·폐기·불변 게시본 조회를 기존 문서 메뉴에 연결했다.
관리자 쓰기/회원 읽기, 조직 경계, revision 충돌, operation_id 재시도, 비동기 편집기와 실패 입력 보존을 구현했다.
게시 상태인 현재 서식만 문서 작성 선택에 표시한다. 새 버전 작성 중 이전 게시본은 조회 가능하나 선택 대상에서는 제외한다.

검증: `npm test --prefix scripts/db-tests` 37개 묶음 통과(기존 시술15/상담12/신규서식10).
`.venv/Scripts/ruff.exe check .` 및 `format --check .` 통과. 별도 정적 검토의 X 닫기/부모 목록 갱신 문제 수정과 회귀 테스트 작성 완료.
Python API/Qt 테스트를 추가했으나 미실행이며 실제 UI 캡처·실제 DB 적용·PostgREST·동시 다중 클라이언트 검증은 대기다.
따라서 코드 구현 완료로 기록하며 기능 상태는 in-progress를 유지한다. DOC-002~004와 고객 동의 완료는 구현했다고 표시하지 않는다.
다른 PC 재현 명령과 호환성 변경은 [적용 안내](../document-versions-release.md)를 따른다.
