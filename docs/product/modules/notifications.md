# 알림·처리함

갱신일: 2026-09-18 · 상태: planned

## 목적·진입점

예약 변경·약속 기한·저장 실패 등 조치가 필요한 항목을 담당자에게 전달한다. 업무 화면에서 진입하고 관리자용 설정은 공통 설정에 둔다.

## 기능 추적

| ID | 우선 | 상태 | 범위 |
| --- | --- | --- | --- |
| NOTI-001 | P0 | planned | 중요도·담당자·기한별 목록 |
| NOTI-002 | P0 | planned | 읽음/처리 완료와 실제 업무 상태 분리 |
| NOTI-003 | P1 | planned | 중복 묶기·알림 빈도·근무시간 설정 |
| NOTI-004 | P1 | planned | 원천 이동 및 담당자 재배정 |

## 데이터 계약

notification_id, source_type/id, assignee_id, severity, due_at, read_at, resolved_at, grouping_key. 식별자에는 조직 경계를 적용한다. 기존 API에 없는 필드는 구현 전에 계약과 마이그레이션을 검토한다.

## 업무·복구 흐름

원천 사건 발생 → 수신자 계산 → 중복 통합 → 전달 → 원천 업무 처리 → 해결 표시. 원천이 취소되면 알림도 취소 상태로 갱신한다.

## 인수 조건

- [ ] 알림을 읽기만 해서는 고객 약속이 완료되지 않는다. 퇴사 직원에게만 미완료 업무가 남지 않게 재배정 대상으로 표시한다.
- [ ] 오류·권한 부족·취소 결과를 사용자에게 표시하고 작성 중 입력을 보존한다.
- [ ] 성공 재시도·중복 이벤트·다른 조직 접근 사례를 테스트한다.

## 단계·검증 기록

소비 메뉴의 P0 흐름에 필요한 최소 기능부터 제공하고, 확장 기능은 별도 검증한다. 2026-09-18 문서 작성; 실환경 검증 없음. 기존 범용 API 존재는 이 문서의 전체 기능 완료 증거가 아니다. 상태 변경 시 [변경 이력](../changelog.md)에 증거와 제한을 기록한다.
