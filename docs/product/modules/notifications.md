# 알림·처리함

갱신일: 2026-10-16 · 상태: 일부 구현(앱 알림 센터 완료, OS 알림 UX-07 진행 중)

## 목적·진입점

예약 변경·약속 기한·저장 실패 등 조치가 필요한 항목을 담당자에게 전달한다. 업무 화면에서 진입하고 관리자용 설정은 공통 설정에 둔다.

## 기능 추적

| ID | 우선 | 상태 | 범위 |
| --- | --- | --- | --- |
| NOTI-001 | P0 | planned | 중요도·담당자·기한별 목록 |
| NOTI-002 | P0 | planned | 읽음/처리 완료와 실제 업무 상태 분리 |
| NOTI-003 | P1 | planned | 중복 묶기·알림 빈도·근무시간 설정 |
| NOTI-004 | P1 | planned | 원천 이동 및 담당자 재배정 |

## 데이터 계약

notification_id, source_type/id, assignee_id, severity, due_at, read_at, resolved_at, grouping_key. 식별자에는 조직 경계를 적용한다. 기존 API에 없는 필드는 구현 전에 계약과 마이그레이션을 검토한다.

## 업무·복구 흐름

원천 사건 발생 → 수신자 계산 → 중복 통합 → 전달 → 원천 업무 처리 → 해결 표시. 원천이 취소되면 알림도 취소 상태로 갱신한다.

## 인수 조건

- [ ] 알림을 읽기만 해서는 고객 약속이 완료되지 않는다. 퇴사 직원에게만 미완료 업무가 남지 않게 재배정 대상으로 표시한다.
- [ ] 오류·권한 부족·취소 결과를 사용자에게 표시하고 작성 중 입력을 보존한다.
- [ ] 성공 재시도·중복 이벤트·다른 조직 접근 사례를 테스트한다.

## 단계·검증 기록

현재 앱은 기존 예약·할 일·고객·회원권 API에서 재료를 불러와 앱 내 알림 센터를 만든다. UX-07은 별도 데이터베이스 없이 데스크톱에서만 운영체제 알림을 선택적으로 보낸다. 사용자가 OS 권한을 허용해야 하며, 예약 시작 60분 전과 할 일 마감 시각이 대상이다. 고객명 등 개인정보는 배너에 넣지 않는다. 사용자·매장별 로컬 저장으로 중복을 막고, 앱이 켜진 동안에만 기존 5분 갱신 주기로 감지한다. 할 일 알림은 담당자가 있으면 담당자에게, 미지정이면 작성자에게만 만든다. 앱이 종료된 동안의 예약 알림 스케줄링, 근무시간·빈도 제어, 예약 담당자별 배달, 설치본 Windows 토스트는 아직 검증하지 않았다.

2026-10-16: UX-07 Tauri 플러그인 연동, 명시적 권한 요청, 사용자 설정, 중복 방지 로직과 집중 단위 테스트 구현. 웹 미리보기에는 OS 알림 설정을 표시하지 않는다. 관련 테스트 통과; 실제 Windows 설치본·실 Supabase 흐름은 검증하지 않음. 전체 기능을 완료로 표시하지 않는다. 상태 변경 시 [변경 이력](../changelog.md)에 증거와 제한을 기록한다.

2026-10-16: TASK-01 할 일 알림 대상 계산을 담당자 기준으로 연결했다. 담당자 지정 할 일은 담당자만 알림을 받고, 담당자가 없으면 작성자만 받는다. 앱 알림 센터와 OS 알림은 같은 사용자별 알림 목록을 쓰므로 대상 규칙을 공유한다. 실조직 데이터와 설치본 OS 전달은 아직 확인하지 않았다.
