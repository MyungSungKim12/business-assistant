# 사진·자료

갱신일: 2026-09-18 · 상태: planned

## 목적·진입점

고객 사진과 거래 증빙 및 교육 자료를 원천 기록에 안전하게 연결한다. 업무 화면에서 진입하고 관리자용 설정은 공통 설정에 둔다.

## 기능 추적

| ID | 우선 | 상태 | 범위 |
| --- | --- | --- | --- |
| MED-001 | P0 | in-progress | 고객 사진 연결과 이미지 유형/용량 검사 |
| MED-002 | P0 | planned | 원본·썸네일 분리와 업로드 진행·실패 재시도 |
| MED-003 | P1 | planned | 촬영일·부위·회차·로트 등 검색 메타데이터 |
| MED-004 | P1 | planned | 보기/내보내기 권한과 삭제·보관 이력 |

## 데이터 계약

media_id, organization_id, customer_id, treatment_id, storage_path, content_type, size, checksum, captured_at, category. 식별자에는 조직 경계를 적용한다. 기존 API에 없는 필드는 구현 전에 계약과 마이그레이션을 검토한다.

## 업무·복구 흐름

파일 선택 → 고객/시술 연결 확인 → 검증 → 업로드 → 서버 등록 → 썸네일 생성. 실패한 파일만 재시도하고 등록만 된 고아 파일은 정리 대상으로 추적한다.

## 인수 조건

- [ ] A고객에 업로드 중 B고객으로 이동해도 A의 사진은 A에만 연결된다. 만료된 다운로드 URL을 갱신하고 접근 불가를 빈 사진으로 숨기지 않는다.
- [ ] 오류·권한 부족·취소 결과를 사용자에게 표시하고 작성 중 입력을 보존한다.
- [ ] 성공 재시도·중복 이벤트·다른 조직 접근 사례를 테스트한다.

## 단계·검증 기록

소비 메뉴의 P0 흐름에 필요한 최소 기능부터 제공하고, 확장 기능은 별도 검증한다. 2026-09-18 문서 작성; 2026-09-29 고객 사진 업로드 API·화면 연결 구현 시작. Supabase에 `022_customer_photos.sql`과 `023_customer_photo_storage_bucket.sql`을 적용하기 전에는 실환경 업로드가 동작하지 않는다. 원본·썸네일 분리, 진행률, 실패 재시도는 MED-002 후속 범위다. 상태 변경 시 [변경 이력](../changelog.md)에 증거와 제한을 기록한다.
