# 예약 공간·장비 적용 안내

작성일: 2026-10-12 · 기능: APT-002 · 상태: 로컬 코드·격리 검증 완료, 실환경 인수 대기

## 제공 범위

- 관리자는 일정 화면의 **공간·장비 관리**에서 예약용 공간과 장비를 등록하거나 사용 중지할 수 있다.
- 서비스마다 필요한 공간·장비 수량을 정한다. 예약 화면은 해당 수량만큼 활성 자원을 기본 선택하며 담당자가 실제 사용할 자원으로 바꿀 수 있다.
- DB는 조직, 활성 상태, 서비스 필수 수량, 중복 선택을 다시 검사한다. 같은 공간 또는 장비를 점유하는 활성 예약은 담당자가 달라도 겹칠 수 없다.
- 예약 취소는 기존 상태 전이를 사용해 자원을 반환한다. 이전 예약의 버퍼가 끝나는 시각과 다음 예약 시작 시각이 같으면 허용한다.
- 자원 등록·수정, 서비스 기준 변경, 예약 저장은 같은 입력의 실패 재시도에 같은 작업 ID를 사용한다. 기존 활성 예약을 무효화하는 사용 중지나 기준 변경은 거절한다.
- 자원 기준이나 새 자원 이름을 입력한 상태에서 서비스 전환 또는 창 닫기를 시도하면 입력 폐기 여부를 확인한다.

## 적용 순서

1. 기존 SQL이 036까지 적용된 환경은 `037_appointment_availability.sql`을 먼저 실행한다.
2. `038_appointment_resources.sql`을 실행한다.
3. 같은 커밋의 서버와 데스크톱을 모두 재시작한다.
4. 관리자 계정에서 공간 2개와 장비 2개를 등록하고 서비스의 필수 공간·장비 수량을 저장한다.
5. 다른 담당자 두 명에게 같은 자원을 같은 시간으로 예약해 두 번째 저장이 거절되는지 확인한다.

마이그레이션은 운영 DB에 자동 실행하지 않았다. `scripts/verify-live-schema.mjs`는 서비스 키가 있는 환경에서 037·038 공개 구조를 읽기 전용으로 확인한다.

## 검증 기록

- 격리 PostgreSQL: 직원·공간·장비 충돌, 필수 자원 누락, 경계 시각, 취소 후 반환, 멱등 재시도, 역할·조직 격리 통과.
- 최종 검토 보완 전 서버/common 전체 기준선: 465개 통과.
- 최종 검토 보완 전 데스크톱 전체 기준선: 255개 통과.
- 최종 보완 후 예약 API·저장소 집중 테스트: 11개 통과.
- 최종 보완 후 예약 화면·클라이언트 집중 테스트: 9개 통과.
- 예약 DB 시나리오와 변경 파일 Ruff 통과.
- 사용자 요청에 따라 최종 보완 후 전체 테스트 묶음은 다시 실행하지 않았다.

## 남은 범위

- 037·038의 실제 Supabase 적용과 Windows 화면 인수
- 지점별 자원 분리와 관리자 예외 승인
- 충돌 시 대체 시간·자원 추천
- 외부 예약 채널과의 자원 동기화
- 방문 처리 후 시술 원장 자동 생성 및 별도 방문 완료 연동

로컬 테스트 통과만으로 APT-002를 `verified`로 올리지 않는다.
