# 일 마감·미수 목록 적용 안내

작성일: 2026-10-08 · 기능: SALE-005 · 상태: 로컬 코드·격리 검증 완료, 실환경 인수 대기

## SQL 적용 순서

사용자는 030번 SQL 실행을 확인했다. 프로젝트 SQL Editor에서 아직 적용하지 않은 파일을 아래 순서대로 각각 실행한다.

1. `migrations/031_customer_product_returns.sql`
2. `migrations/032_sale_cart_discounts.sql`
3. `migrations/033_sale_daily_closings.sql`

이미 실행한 파일은 다시 실행할 필요가 없다. 이 작업에서는 Supabase 운영 DB에 접속하거나 SQL을 실행하지 않았다. 033 적용 후 서버와 데스크톱을 현재 소스와 같은 버전으로 재시작해야 한다.

## 사용하는 방법

재무의 **미수·일 마감**을 열고 영업일을 선택한다. 화면은 한국 시간 날짜로 결제수단별 수납·환불 합계와 예상 현금 시재를 계산하며, 현재 일부 수납 상태인 고객별 미수액을 보여준다. 마감 권한이 있는 owner/admin은 실제 현금 시재와 사유를 입력하고 확인해 마감한다.

마감이 끝난 날짜를 다시 저장하면 원래 마감은 보존되고, 사유·변경 전후 시재·수정자·수정 시각이 새 버전 이력으로 추가된다. 오래된 버전에서 보낸 동시 수정은 거부된다. 재요청에는 같은 작업 식별자를 써 중복 기록을 막는다.

## 계산 및 제한

- 예상 현금 시재 = 해당 영업일 현금 수납 − 해당 영업일 현금 환불. 카드와 이체 환불은 각각의 결제수단 합계에만 포함한다.
- 미수는 `collecting` 상태 장바구니의 총액에서 현금·카드·이체 및 회원권 사용액을 빼고, 같은 판매건에 기록된 환불액을 더해 산출한다. 취소/환불 종료 건은 미수 목록에서 제외한다.
- 마감과 수납/환불 입력은 조직·한국 시간 영업일별 잠금으로 직렬화한다. 마감 뒤에는 해당 날짜로 귀속되는 수납/환불을 추가할 수 없다. 영업일을 다시 열거나 과거 날짜로 소급 입력하는 기능은 없다.
- 영업일 경계에서 자정 전후의 실제 현금 인수와, 마감 후 실수로 늦게 확인한 PG/현금 건의 운영 정책은 매장 인수에서 확인해야 한다.
- 화면의 미수 목록은 현재 미수만 보여준다. 과거 미수 변동 리포트, 매출원가·세금·직원 수당·현금 시작 시재를 포함한 손익 정산은 별도 기능이다.
