# SALE-001 방문별 결제 장바구니 적용·검증 기록

작성일: 2026-10-02  
상태: 코드 보완 및 범위별 검증 진행, 실환경 적용 전 `in-progress`

## 구현 범위

- 고객별 방문과 1:1 검토 장바구니
- 시술에서 전달한 불변 결제 초안 가져오기
- 수량·검토 단가·담당자 수정, 사유 있는 제거와 복원
- 서버 계산 소계·할인·청구 예정 합계
- 장바구니 검토 완료와 빈 방문 취소
- 예상 버전 충돌, operation ID 정확 재시도, 조직·관리자 권한
- 매출·지출 메뉴의 고객/방문·초안/항목·합계 3열 화면
- 일부 조회 실패에서 성공한 열 보존, 저장 결과 불명확 시 같은 요청 재시도

장바구니와 검토 완료는 실제 수납이나 확정 매출이 아니다. `finance_transactions`, 재고, 회원권, 직원 수당은 변경하지 않는다.

## 적용 순서

1. 대상 Supabase 프로젝트의 migration 001~023 적용 상태를 확인한다.
2. `migrations/024_visit_sale_carts.sql`을 적용한다.
3. 새 서버와 데스크톱을 함께 배포한다.
4. 테스트 조직에서 owner/admin과 member 계정으로 아래 인수 흐름을 확인한다.

이번 작업에서는 운영·실사용 Supabase DB에 migration을 적용하지 않았다.

## 2026-10-02 추가 보완 — 입력 보호와 실패 복구

SALE-001은 계속 `in-progress`다. 이전의 로컬 검증 결과는 당시 범위이며 입력 보호 전체의 완료 근거가 아니다.

- 고객·방문·항목 전환, 새로고침, 닫기와 Enter 종료에서 미저장 입력을 확인한다. 취소하면 기존 선택과 입력을 유지한다.
- 요청 처리 중 및 저장 결과 불명확 상태에서는 고객·방문·항목 선택을 잠근다. 통신 실패의 재시도는 동일 operation ID를 유지한다.
- 방문 없는 고객으로 이동할 때 이전 고객의 항목·금액·편집기를 지운다.
- 방문 생성 응답을 직접 표시하여 불필요한 추가 조회를 없앴다.
- 400/401/403/404/409/422의 확정 거절은 통신 실패와 구분하고 같은 잘못된 요청의 무한 재시도를 해제한다. 입력은 보존하며 충돌 시 새로고침 후 재검토를 안내한다. 자동 충돌 병합은 제공하지 않는다.
- 검토 완료 방문도 조회 대상에 포함하고, 취소된 장바구니의 변경 버튼은 비활성화한다.

검증 담당: Codex. 기본 `.venv/Scripts/python.exe`와 `uv run --all-packages python`은 출력 없이 exit 1로 종료되어 지원 대상 Python 3.13 테스트를 완료하지 못했다. 회사 PC 정책이 원인인지 이번 실행 결과만으로 단정하지 않는다.

대신 앱에 포함된 Python 3.12.14에 기존 site-packages 및 desktop/common 소스 경로를 지정하여 `-m pytest apps/desktop/tests/test_sale_cart_page.py -q`를 실행: **13 passed**. 이는 보조 환경의 한정 검증이다. 같은 환경에서 데스크톱 전체 테스트는 Python 버전별 pydantic_core 바이너리 불일치로 수집 단계 실패했다. 전체 회귀 통과로 기록하지 않는다.

새 화면 캡처·실제 Supabase 연동·다중 연결 동시성 검증 없음. 기존 1100/1440 이름의 캡처는 생성 코드의 고정 창 크기 때문에 서로 다른 너비 검증 근거로 사용하지 않는다. 복합 수납 전에는 DB 입력·동시성 계약, 권한별 초안 조회, 전체 회귀 검증을 계속 보완해야 한다.
