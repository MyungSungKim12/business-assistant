# 안드로이드 휴대폰 전화 연동 테스트

2026-10-30 업데이트: **0.3.0(versionCode 4) APK**에는 동의한 매장의 번호부를 약 15분마다 자동 전체 갱신하는 기능과 마지막 동기화 시각·오래됨 표시가 있습니다. 앱 재진입 시 5분 이상 오래되었으면 갱신을 예약합니다. Android 절전·통신 상태에 따라 지연될 수 있습니다. 기존 APK는 재설치(업데이트)해야 반영됩니다. 마지막 동기화가 없거나 30분 이상 지났으면 PC 전화 전송을 보류하므로 먼저 고객 번호를 동기화하세요. 알 수 없는 번호를 서버에 보내 동기화를 대신하지 않습니다. 동의 해제·매장 변경·로그아웃은 최초 동기화 중에도 무효화됩니다. 임시 API 주소가 바뀌면 아래 테스트 실행 절차로 새 주소의 APK를 만드세요. [검증·제한](../product/audits/2026-10-30-followup-hardening.md).

기준일: 2026-10-23 · 대상: `apps/android-companion` 디버그 앱

현재 버전은 **0.2.0**이다. 휴대폰 고객 알림을 제거하고 **같은 계정·같은 매장 PC 프로그램에 고객 알림을 전달**한다. PC 전달에는 번호부 동기화와 별도의 동의가 필요하다. 10/23 실제 S23→PC 앱 내부 카드 성공을 사용자가 확인했다. 이후 최소화·트레이용 독립 알림창을 추가했으며 이 창의 실수신 인수는 남아 있다.

## PC 알림창 확인 (2026-10-23)

- PC 네이티브 앱을 최신 코드로 실행하고 같은 계정·매장으로 로그인한 뒤 최소화하거나 X로 트레이에 숨긴다. 완전 종료/로그아웃/앱 잠금 상태는 수신 대상이 아니다.
- 등록한 고객 번호에서 S23으로 전화하면 화면 오른쪽 아래에 독립 창이 등장하고 테두리가 3회 강조된다. 동작 줄이기 설정에서는 움직이지 않는다.
- ‘메모 작성’은 PC 메인 창을 복원하고 해당 전화의 메모를 연다. 이미 쓰고 있는 메모는 덮어쓰지 않는다. ‘닫기’는 그 알림을 닫는다. 수신 시점 기준 약 2분이 지나면 사라진다.
- 고객 1명이 정확히 일치하면 메모·주의사항/태그·실제 방문·다음 예약·최근 완료 시술과 최근 사진을 이어 불러온다. 빈 정보와 조회 실패를 구분하며 실패 항목은 ‘다시 불러오기’로 재시도한다. 고객 메모 전체 보기/사진 확대는 알림창 안에서 동작한다.
- ‘고객 상세 보기’는 검색 없이 해당 고객 화면을 연다. 동일 번호가 여러 고객에 등록돼 있으면 고객별 상세 버튼에서 선택한다. 일부 정보는 예약/시술 등의 해당 기능 권한이 필요하며, 권한이 없거나 서버 연결이 실패하면 그 항목만 조회 실패로 표시한다.
- 이 창은 Windows 기본 배너와 별개이며 Windows 알림 설정을 켤 필요가 없다. 예약·할 일의 기본 배너는 앱 설정의 Windows 알림/테스트 버튼으로 확인한다.
- 이번 PC 변경만으로 휴대폰을 재설치하거나 SQL을 실행할 필요는 없다. 임시 터널 주소를 바꾸면 APK 재설치는 여전히 필요하다.

## S23에서 Wi-Fi·USB 없이 LTE/5G로 테스트하기

현재 PC의 유선 인터넷과 S23의 모바일 데이터를 사용한다. PC API에 임시 HTTPS 주소를 연결하므로 같은 네트워크가 필요하지 않다. 0.2.0 APK 빌드와 Kotlin 6 tests/API 21 tests/React 27 tests/게이트웨이 1 test를 통과했다. 실제 S23 수신→PC 표시·메모 인수는 사용자가 수행해야 한다.

1. 터미널 1에서 평소처럼 `D:\ms\business-assistant`로 이동한 뒤 `.\run-app.cmd`를 실행한다. 이미 실행 중이면 그대로 둔다. 이 방식은 `APP_API_HOST=0.0.0.0`나 인바운드 방화벽 개방이 필요하지 않다.
2. 터미널 2에서 아래 명령을 실행한다.

```powershell
cd D:\ms\business-assistant
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-android-mobile-test.ps1
```

3. 스크립트가 임시 Cloudflare HTTPS 주소 생성 → 그 API 주소를 넣은 APK 빌드 → 번호 매칭 단위 테스트를 실행한다. 마지막에 출력되는 `/download/…/app-debug.apk` 주소를 S23의 Samsung Internet/Chrome에서 연다.
4. 기존 앱 위에 APK를 업데이트 설치한다. **PC와 같은 계정** 로그인 → **PC와 같은 매장** 선택 → 고객 번호 동기화 → **PC 프로그램에 알림을 표시하는 데 동의** 체크 → 전화 식별 역할 허용 순서로 진행한다. PC 앱은 현재 소스 반영을 위해 한 번 닫고 `run-app.cmd`로 다시 열어 두는 것을 권장한다.
5. 전화기 연락처에 저장된 번호로 시험한다면 앱의 `연락처에 저장된 번호도 식별하기 (선택)`를 눌러 설명 확인 후 Android 연락처 권한을 허용한다. 해당 권한 없이 시험할 때는 연락처에 없는 번호로 전화한다. 앱은 연락처 목록을 조회/업로드하지 않으며 권한은 Android가 저장된 연락처의 전화도 통화 선별 앱에 전달하기 위한 조건이다.
6. 휴대폰 상태가 `전화 식별 역할: 켜짐`, `PC 알림 전송: 켜짐`인지 확인한다. 등록·동기화된 고객 번호로 S23에 전화를 건다. **PC 프로그램 오른쪽 아래**에 고객 이름/번호 카드가 표시되면 `메모 작성`을 눌러 기록한다. 알림이 없으면 휴대폰 앱의 `최근 수신 확인`을 확인한다. `PC 알림 서버에 수신 전화 전달 완료`인데 PC에 안 뜨면 계정·매장·잠금 상태를 확인한다. 시각/처리 결과만 기기에 암호화 저장하고 번호/이름은 진단 기록에 넣지 않는다.

PC가 최소화되어 있으면 Windows 배너는 PC 앱 설정의 데스크톱 알림을 켠 경우에만 표시된다. 우선 PC 앱을 열린 상태로 시험한다. PC 앱이 잠겨 있으면 알림 조회를 멈추고 개인정보를 표시하지 않는다.

PC 앱과 두 번째 터미널을 테스트 동안 켜 둔다. 터널은 고객 번호부/번호조회/전화 메모/수신 이벤트 POST, 인증/조직 목록, 임의 토큰이 있는 APK 다운로드 경로만 전달하고 다른 업무 API와 로컬 파일은 차단한다. PC 이벤트 조회 GET은 외부에 노출하지 않는다. 사용자 인증과 조직 권한은 기존 API가 계속 검사한다. 다운로드 주소를 타인에게 공유하지 않는다. 테스트 종료는 두 번째 터미널에서 Ctrl+C를 누른다.

명령을 반복 실행했을 때 이 프로젝트의 테스트 연결이 이미 살아 있으면 기존 연결을 확인해 재사용하고 종료한다. 따라서 기존 연결이 유지되는 동안에는 APK를 다시 설치할 필요가 없다. PC의 APK 빌드 주소가 다른 주소로 바뀌어 있거나 파일이 없으면 기존 연결 주소로 다시 빌드하며 업데이트 설치가 필요하다고 안내한다. 다른 프로그램이 8789를 사용하면 자동 종료하지 않는다.

기존 연결을 완전히 종료한 뒤 새로 실행하면 주소가 바뀌므로 새 APK를 내려받아 덮어 설치한다. 아직 프로덕션 배포가 아니며 Cloudflare Quick Tunnel은 테스트용이다. 터널이 회사 네트워크에서 연결되지 않으면 오류 로그와 해당 네트워크의 허용 여부를 확인한다.

아래는 같은 Wi-Fi 또는 USB가 있는 경우의 대체 절차다.

이 앱은 Android 10(API 29) 이상에서 동작하는 별도 Android 앱이다. 고객 번호부와 전송 대기는 Android Keystore AES-GCM으로 기기에 암호화 저장한다. 수신 통화는 즉시 허용하고, 전송 동의 후 알려진 고객 번호만 PC 알림 서버에 전달한다. 통화 녹음이나 통화 내용 자동 수집은 하지 않는다.

## 1. PC와 휴대폰 준비

PC에 Android Studio를 설치한 뒤 Android Studio의 SDK Manager에서 다음을 설치한다.

- Android SDK Platform 35
- Android SDK Build-Tools 35
- Android SDK Platform-Tools
- Gradle 8.10.2에서 실행 가능한 JDK 17 또는 21. 현재 PC는 기존 `JAVA_HOME`의 JDK 21로 빌드했다. 최신 Android Studio의 JBR 25는 이 Gradle 버전과 맞지 않는다.

실제 통화 시험에는 Android 10 이상 휴대폰과 SIM/eSIM이 필요하다. PC와 휴대폰을 같은 개인 Wi-Fi에 연결한다. Android Emulator는 PC 서버 API와 수동 전화번호 확인은 시험할 수 있지만 실제 이동통신 수신 전화 시험은 할 수 없다.

## 2. PC 서버 실행

기존 실행 명령을 그대로 사용하면 된다. PowerShell 첫 번째 창에서 저장소 루트로 이동해, 그 실행 세션에서만 API가 모든 로컬 네트워크 인터페이스를 듣도록 설정하고 앱을 연다.

```powershell
cd D:\ms\business-assistant
$env:APP_API_HOST = '0.0.0.0'
.\run-app.cmd
```

이 명령은 데스크톱 앱과 API를 함께 실행한다. 앱 창을 닫으면 이 명령이 시작한 API도 종료된다. 이미 떠 있는 API가 있으면 `run-app.cmd`가 그것을 재사용하므로, 기존 API가 `127.0.0.1`에만 묶여 있다면 먼저 해당 서버를 종료한 다음 실행한다. 별도로 API만 시험할 때는 같은 환경 변수 설정 뒤 `powershell -ExecutionPolicy Bypass -File .\scripts\run-server.ps1`를 쓸 수 있다.

휴대폰과 PC가 같은 Wi-Fi인지 확인하고 `ipconfig` 출력에서 PC의 해당 Wi-Fi 어댑터 IPv4 주소를 확인한다. 아래 예시의 `192.168.0.20`을 그 주소로 바꾼다. Windows Defender Firewall이 물으면 사설 네트워크에서만 허용한다. 연결이 안 되면 사설 네트워크 프로필에 대해 TCP 8000 인바운드 허용 규칙을 추가한다. 서버 포트 8000을 인터넷에 공개하거나 공용 Wi-Fi에서 사용하지 않는다.

## 3. 디버그 APK 빌드

두 번째 PowerShell 창에서 같은 저장소 루트에서 실행한다.

```powershell
cd D:\ms\business-assistant
powershell -ExecutionPolicy Bypass -File .\scripts\build-android-companion.ps1 -ApiBaseUrl 'http://192.168.0.20:8000/api/v1/'
```

첫 실행 시 스크립트는 공식 Gradle 8.10.2 배포본을 내려받아 SHA-256을 검사한 뒤 빌드한다. 이후에는 PC의 로컬 캐시를 재사용한다. 앱 의존성은 Google Maven 및 Maven Central에서 내려받는다. 출력 APK는 다음 위치에 생성된다.

```text
apps/android-companion/app/build/outputs/apk/debug/app-debug.apk
```

Android Studio를 쓰고 싶다면 `apps/android-companion` 폴더를 열고 Gradle 동기화 후 `app`의 debug 구성을 실행해도 된다. 휴대폰에 APK를 복사해 직접 설치할 때는 Android에서 이 출처의 앱 설치를 허용해야 한다.

USB 디버깅을 켜고 PC에 연결한 경우 아래 명령으로도 설치할 수 있다.

```powershell
& "$env:ANDROID_HOME\platform-tools\adb.exe" devices
& "$env:ANDROID_HOME\platform-tools\adb.exe" install -r .\apps\android-companion\app\build\outputs\apk\debug\app-debug.apk
```

## 4. 로그인과 수신 전화 식별 설정

1. 휴대폰에 디버그 APK를 설치하고 실행한다. 로그인 화면의 API 주소가 PC Wi-Fi IPv4와 `:8000/api/v1/`인지 확인한다.
2. 기존 Business Assistant 계정으로 로그인하고 테스트 조직을 선택한다. 로그인 계정은 해당 조직의 고객 관리 권한이 있어야 한다.
3. 고객 이름과 전화번호를 확인하고 `동의하고 고객 번호 동기화`를 누른다. 이는 선택한 조직의 활성 고객 번호를 이 기기에 보관하는 것에 대한 동의다.
4. `수신 전화 고객 식별 권한 켜기`를 누르고 Android 시스템 화면에서 Business Assistant를 통화 선별 앱으로 선택한다.
5. 고객 번호 동기화 후 PC 전송 동의를 체크한다. 휴대폰 알림 권한은 필요하지 않다. PC도 같은 계정/매장으로 로그인해야 한다.

0.1.1부터 연락처에 저장된 번호도 식별하기 위한 `READ_CONTACTS` 권한을 선택적으로 요청한다. 앱의 설명 대화상자를 확인하고 OS 권한을 허용하면 저장된 연락처 전화도 Android 통화 선별 서비스에 전달될 수 있다. 거부하면 연락처에 없는 번호만 대상으로 시험한다. 앱은 연락처 목록을 읽거나 업로드하지 않는다. 권한은 Android 앱 설정에서 철회할 수 있다. 통신사/기기 기본 전화 앱과 제조사 설정에 따라 표시 방식이 달라질 수 있다.

## 5. 실제 통화와 메모 저장 확인

1. 선택한 조직에서 활성 고객 한 명의 전화번호를 시험 발신 번호로 설정한다. 한국 번호는 `010-1234-5678` 또는 `+82 10 1234 5678`처럼 입력해도 된다.
2. 그 번호가 휴대폰 연락처에 있다면 앱에서 선택 연락처 권한을 허용했는지 확인한 뒤 다른 전화기로 해당 번호에 전화를 건다.
3. 휴대폰은 평소처럼 울려야 한다. 고객 일치 시 휴대폰 고객 알림 대신 서버 전달 작업을 예약한다.
4. 같은 계정·매장 PC 프로그램 오른쪽 아래 고객 카드에서 `메모 작성`을 누른다. 다른 화면에 작성 중이던 입력이나 먼저 열린 전화 메모를 새 전화가 덮어쓰지 않아야 한다.
5. 고객을 선택하고 통화 메모를 저장한다. 고객 상세 활동 이력에서 `전화 상담`을 확인한다. 사용자가 메모를 저장할 때만 원장에 기록한다.

중복 번호는 임의로 한 명을 고르지 않는다. 화면에서 고객을 직접 선택한 뒤 저장한다. 고객이 조회되지 않으면 수동으로 번호를 입력해 `고객 확인`을 누르면 서버 조회 경로를 따로 시험할 수 있다.

## 6. 개인정보 저장과 정리

- `동기화 해제 및 번호 삭제`는 이 기기의 고객 번호부와 동의 표시를 지운다.
- 로그아웃은 refresh token과 동기화 번호부도 지운다.
- 조직을 바꾸면 기존 조직 번호부를 지우고 새 조직 동의를 다시 받는다.
- Android 설정에서 Business Assistant의 통화 선별 역할을 해제하면 자동 수신 식별을 멈춘다.
- PC 전송 동의를 해제하면 암호화 전송 대기를 지우고 후속 이벤트를 전송하지 않는다. 이미 서버에 전달된 최근 알림은 최대 2분 후 사라진다. API 재시작/PC 미접속 동안 수신 이력 보존과 다중 서버 공유 저장은 배포 단계 후속이다.
- 디버그 빌드는 PC의 HTTP 주소 사용을 허용한다. 공개 배포에는 HTTPS 주소와 별도 release 서명/보안 검토가 필요하다. 디버그 APK를 인터넷에 공개하지 않는다.

## 제한과 검증 상태

Android APK 빌드/Kotlin 6건, API 21건, PC React 27건과 양쪽 타입 검사, 게이트웨이 1건을 통과했다. 임시 HTTPS에서 health 200, 미인증 수신 이벤트 POST 401, APK 다운로드와 로컬 빌드 해시 일치를 확인했다. S23 실제 전화→PC 인수는 대기다. Android 통화 선별 및 선택 연락처 권한 조건은 [Android 공식 안내](https://developer.android.com/reference/android/telecom/CallScreeningService)를 따른다.
